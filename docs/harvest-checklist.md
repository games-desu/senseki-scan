# 辞書収穫用の録画チェックリスト（2026-08-30版）

ランクマッチ以外（フレンド戦・COM戦等）で辞書の未収穫を埋めるための録画リスト。
**録画設定はいつも通り（1080p・60fps・6〜12Mbps・OBS元録画）**。複数試合を1本にまとめてOK。
撮れたら samples/ に入れて「収穫用」と伝えてください。ラベルは映像から目視確定するので、
**SENSEKI FEVERへの登録は不要**です。

**運用**: 収穫が終わるたびにClaudeがこのファイルのチェックを更新してコミットします。
進み具合は https://github.com/games-desu/senseki-scan/blob/main/docs/harvest-checklist.md でいつでも確認できます。

| ラケット発動バナー | **ランクマと同一**（アプリ側にバグがあった） | 下記 |

**ラケットも形式は同じでした**。当初「オフラインはキャプション形式で別物」と書きましたが誤りで、
正体は**アプリのバグ**でした。バナーのリボンは**ショットごとに色が違う**（ファイアバー=橙／
マジック=青紫／**ドッスン=灰**／**ドロドロ=茶**）のに、検出条件が「高彩度のリボンが下にあること」
だったため、**灰・茶のリボンのラケットが丸ごと検出できていなかった**（実測 ドッスン sat=0.000）。
「ドッスンは前回、画面端で見切れて収穫失敗」と記録していたのも、実はこれが原因でした。

- 対策: リボン判定を「高彩度 **または** 帯の輝度分散>=35 かつ 文字幅>=660」に緩和（vision.js）
- 退行チェック: **ランクマ素材（2026-08-30 01-44-03・30分）で通過イベント28件が前後で完全に不変**
- 効果: このパイロットの検出が **0件 → 4件**（ドロドロ×2・ドッスン×2）。
  同じラケットの別々の発動どうしが **1.000 で一致**＝プロファイルは安定
- 収穫: **ドッスンラケット・ドロドロラケット**（racketBanners 84→88本／19→21種）

### A の結果メモ（2026-09-05）

- 同じラケットの別々の発動どうしは全9種で **0.999〜1.000 で一致**（プロファイルは安定）
- **白リボンのバナーが未対応だった**: フィーバーショット（マイラケット・白×灰の縞）と
  ビューゴーショット（白×水色の縞）はリボン自体が「明るい無彩色」で文字と区別がつかず、
  文字ボックスが帯いっぱい（幅1790）に膨らんでプロファイルがリボンで汚染されていた。
  → findBanner に「文字ボックスが帯の75%超なら、黒縁に両側を挟まれた白ランだけで取り直す」分岐を追加
  （色リボンのバナーは分岐に入らないので従来の検出結果は不変）
- 収穫前は **4種が既存ラケットに0.93の閾値を超えて化ける状態だった**（無警告の誤名になりうる）:
  ファイアショット→アイス 0.944／ファイアフラワーブースト→アイスフラワー 0.957／
  ブルブースト→メタル 0.960／キラーブースト→スター 0.932。収穫後は本人が 0.997〜1.000 で勝つ
- ついでに旧辞書（2026-08-21 の side帰属×GT 自動収穫分）の**誤ラベル10本を除去**:
  カーブ×6・たつまき×2 がトゲゾーと同一（1.000）、オシダシー×2 がサンボと同一（0.999）だった。
  同じ絵に別ラベルが付いていると同点で先に並んだ方が無警告で勝ってしまう
