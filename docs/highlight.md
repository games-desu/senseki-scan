# ハイライト生成（得点シーンの自動切り抜き）— 設計と検証

初版 2026-09-02（v0.4.0）。**この機能を触るときは先にこのファイルを読む。**
ユーザー要望: 読み込んだ動画から ①サーブ開始〜得点までの区間 ②得点直前の数秒 を自動で切り抜き、
気に入らなければ手で直せて、②は1試合単位で繋げたダイジェストも出せること。
**Xに投稿するときプレイヤー名が映らないように**、名前が載る画面（ポイント間のスコアバナー等）は必ずカットする。

## 構成

| ファイル | 役割 |
|---|---|
| `app/renderer/rally.js` | Phase A（得点HUD→ポイント境界）。`tools/rally.js` の同梱版。readSide が領域セットを受け取れる |
| `app/renderer/highlight.js` | 認識ロジック。試合窓 → HUD走査 → ポイント化（純粋関数）→ 切り抜き区間 → 名前ガード |
| `app/renderer/hl-ui.js` | UI（パネル・一覧・区間調整モーダル・書き出し）。index.html のメインスクリプトの後に読み込む |
| `app/main.js` | `hl-*` IPC。同梱 ffmpeg で切り抜き（再エンコード）と連結（copy） |
| `tools/highlight-node.js` | ヘッドレス検証。renderer の3ファイルをそのまま vm に載せ、ffmpeg の生フレームで readFrame→buildPoints |

ffmpeg は npm の `ffmpeg-static`（gyan.dev essentials 6.1.1・libx264/aac 入り・GPL）。
`build.asarUnpack` で asar の外に出し、main.js が `app.asar.unpacked` に読み替える。
**npm 12 は依存の install script を既定でブロックする**ため、`npm install` だけでは exe が落ちてこない。
`npm run dist` の前に `predist` が存在確認して止める → `node node_modules/ffmpeg-static/install.js` で取得。

## 認識の流れ

1. **試合窓**: `V.scan`（1秒刻み・戦績CSV解析と同じ）→ レート検証ゲート（`gateRatings`・index.html から関数化）→
   `Highlight.matchWindows`: vs → (winner) → rating で1窓。groupMatches と同じく「前試合が閉じる前の vs は無視」。
   レートパネルの無い録画（COM戦）は1窓に複数試合が入るが、次段の**得点リセット**で分かれる。
   戦績CSV解析が済んだファイルはシーン走査を `SCENE_CACHE` から再利用する。
2. **HUD走査**: 窓内を **1.0秒刻み**でシークし `readFrame`（コーナーHUD + classify + ポイント間バナー）。
   消灯は2.4秒以上・ポイントは2秒以上なので取りこぼさない（0.5→1.0 で走査時間半減・10-44-35 で全ポイント維持を確認）。
   **時間の主因はシーク**（OBS録画はキーフレーム2秒間隔なので1シーク＝最大120フレームのデコード）。
   走査回数の内訳（38分録画）: シーン走査1秒刻み≒2300回（CSV解析済みなら再利用でゼロ）＋HUD走査≒試合時間の秒数＋
   境界精密化≒ポイント数×12＋サムネ。精度を落とさず減らせる余地はほぼここまで
3. **ポイント化** `buildPoints`（純粋関数）: HUD点灯セグメントを作り、「直前に読めた得点」と「次に読めた得点」を
   比べる（数字未描画の一瞬のセグメントは飛ばす）。
   - 得点が動いた → ポイント（勝者は `Rally.whoScored`）
   - 総得点が減った（6-4 → 0-0）→ 試合の切り替わり。直前の状態から**最終ポイントの勝者**を一意に決める
     （通常: 片側だけ6ならその側 / デュース: Adv.側）。窓の最後のセグメントも同じ扱い
   - 同じ得点のまま短い消灯（≤4.5秒・リプレイ等）→ 同じポイントの続き（始点を維持）
4. **境界の精密化**: 二分探索で消灯開始を 1/60秒・復帰を 1/30秒まで詰める（消灯開始＝バナー出現の直前なので精度が要）。
5. **切り抜き区間** `clipRanges`: 終端 = 消灯 **−0.033秒（2コマ前）**。
   ① 復帰〜終端 / ② max(復帰, 終端 − N秒)〜終端（N既定5・2〜20）。③ 試合ごと＝チェックしたラリーの①をつないだもの。
   **始点（fresh）**: イントロ直後の復帰では VS画面（名前入り）の残像が HUD 復帰後も 0.25〜0.5秒残る
   （実測3素材 intro_*.jpg・ユーザーが実機で「うっすら名前」を確認 2026-09-02）→ 試合の最初のポイントと
   長い演出のあとのポイントは `fresh` を立て、始点を +1.0秒（INTRO_LEAD）ずらす。編集UIでもそこは赤
   **経緯**: 初版 −0.15 → ユーザー要望「最後のショットの行く末をぎりぎりまで」で +0.05 に → **実機（フィーバーダブルス・草）で
   終端に名前バナーが映った**（2026-09-02）。原因は二分探索の遅れ側の誤差: シーク直後に前のフレームが残る（ステイル）と
   「まだ点灯」と誤読する。ヘッドレス検証（ffmpegの正確なフレーム）では起きない。→ `confirmOff`（消灯側から手前へ1コマずつ
   読む確認パス。ステイルは安全側にしか外れない）を足し、終端は −0.033 に。ユーザー確認済みの安全値は旧推定 −0.12
6. **名前ガード** `guardRange`（書き出し直前・既定ON）: 区間の末尾/先頭/内部(0.25秒刻み)を読み、
   バナー・VS画面・勝敗パネルが映るフレームがあれば区間を詰める。手修正で終端を消灯の後ろに置いても、ここで手前に戻る。

### プレイヤー名が映る画面（＝映してはいけない）
- **ポイント間の黒いスコアバナー**（画面下中央・`名前 [icon] n - m [icon] 名前`・ダブルスは2行）。
  **コーナーHUD消灯 → バナー出現は +0.117秒（60fpsで7フレーム）で完全に一定**
  （2026-09-02・60fps実測40か所: 10-44-35 砂クラシック18 / 00-08-01 フィーバー12 / 01-57-16 ダブルス720p10、min 0.116 max 0.117）。
  → 終端 = 消灯−0.033 でバナーまで9コマ。バナー消灯 +1.7秒 → HUD復帰 +2.7秒。
- **最終ポイント**はバナーが出ず、勝敗パネル（名前入り・classify=winner）が消灯の **+3.77〜3.80秒** に出る（実測7件）。
  その間はコイン演出のみ。編集UIの赤い区間は最終ポイントだけ +3.5秒から
- バナーの検出はピップ（deuce-pips.md: 左ピル x667-848 / 右 x1071-1252, y977-1014）を `Rally.readSide` で読む（present のみ使う）。
- VS画面 / 勝敗パネル（classify の vs / winner）。
- 試合中の HUD・ショット名の吹き出し・SMASH 等のラベルには名前は無い（実フレームで確認）。

## 設計を縛る実測（2026-09-02 ヘッドレス検証）

- **砂コートはHUD消灯中でも7スロットが全部 'Y' に読める** → readSide の present に **ピル地の占有率 fill ≥ 0.25** を追加
  （旧: スロット構成だけ）。修正前は「7-7」の偽HUDが多発しポイントが崩壊。
  実測 fill: 点灯時 min 0.412〜0.421（p50 0.44）/ 消灯時は 0.000 が大半（フィーバーの演出で 0.9〜1.0 になる
  フレームがあるが、スロット条件で落ちる）。`tools/rally.js` にも同じ修正を入れた
- **数字未描画（numW<30）の一瞬のセグメント**が境界に挟まると、前後比較が「読めない」で切れて
  ポイントを取りこぼす → 「直前に読めた状態」との比較に変更（上記3）
- ウォームアップ（0-0）→ 1ポイント目は **HUDが消えない**（10-44-35: 25.5〜46.5 が連続点灯）→ 1ポイント目の
  ①区間はウォームアップを含む。②は末尾N秒なので影響なし。必要なら手修正
- フィーバー最終ポイントで HUD が 32秒点灯し続けた例（00-08-01 g3）。演出込みだが害はない

## 書き出し（main.js `hl-cut` / `hl-concat`）

```
ffmpeg -ss S -i IN -t D -map 0:v:0 -map 0:a:0? [-vf crop=w:h:x:y,scale=-2:'min(ih,1080)']
  -c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p -c:a aac -b:a 160k -ar 48000
  -movflags +faststart -avoid_negative_ts make_zero -y OUT
```
- `-ss` を `-i` の前に置いて再エンコード → キーフレーム位置に関係なく**フレーム単位で正確**（copy だと最大2秒ずれる）
- 実測: 1080p60 の5秒クリップ 1.4秒（この機での libx264 veryfast）。NVENC も同梱ビルドで使えるが、
  全ユーザーで同じ結果にするため未採用
- 「ゲーム画面の位置」（SETTINGS.gameRect）があれば crop、1440p以上は 1080p へ縮小（チェックで切替）
- 連結（ffmpeg 呼び出しは `app/hl-ffmpeg.js` に分離・node 単体でテスト可）
  - つなぎ目「なし」: 同一設定で切ったクリップを concat demuxer で `-c copy` 連結（一時フォルダに切ってから連結し、削除）
  - つなぎ目あり（既定＝ディゾルブ0.3秒・2026-09-05に0.5から短縮「動画が短く感じる」。黒フェード/ワイプ/スライドも）: `xfade` + `acrossfade` で重ねながら再エンコード。
    offset は「ここまでの出力長 − D」（長さは `ffmpeg -i` の Duration・0.01秒精度なので 0.02秒手前に置く）。
    全入力を同時に開くため **10本ずつ中間ファイルに段階連結**（CHUNK=10・つなぎ目は上の段で付く）。
    実測: 5秒×3本 6.6秒（14.1秒の出力）／12本 37.5秒。ユーザー要望「バツっと切れすぎ」（2026-09-02）
- ファイル名: `録画名_試合n_Pkk_スコア_自分|相手[_ラリー全体].mp4` / `録画名_試合n_ダイジェスト.mp4`
- 動画のパスは preload の `webUtils.getPathForFile`（Electron 32+ で File.path は廃止）

## UI（hl-ui.js）

- パネルは番号付きの流れ（ユーザー要望 2026-09-02「どこで何を選ぶか分かりづらい」）:
  **1. 切り抜く区間**（得点前N秒 / サーブから得点まで / 試合ごと）→ **2. 録画** → 解析 →
  **3. 保存する区間にチェック**（既定＝自分の得点。試合ごとに切り替えると全ポイント）→
  **4. 保存形式**（区間ごとに1本ずつ / 1本に繋げる＋「試合ごとに分ける」）。試合ごとのときは「試合ごとに保存 / 全試合を1本に」
- 一覧: 試合ごとにポイント行（サムネ・P番号・自分/相手・スコア遷移・マッチ決定・選んだ種類の区間・手修正マーク）
- 区間の調整モーダル: 切り出しプレビュー（gameRect を CSS で再現）・タイムライン（緑=HUD点灯・赤=消灯後＝名前が映る）・
  ハンドルのドラッグ・±1s/±0.1s・区間再生・開始/終了をここに・自動に戻す・Space/←/→/Esc。
  終端を消灯より後ろに置くと警告（ガードONなら書き出し時に詰める）
- 区間調整モーダルに「前/次のポイント」（PageUp/PageDown・いまの区間は決定して移る）と「この区間を保存する」チェック
- 書き出し: 進捗は一覧の上と保存ボタンの横の2か所（247ポイントの実機で「押しても反応がない」に見えた）。
  名前ガードは自動区間なら末尾/先頭だけ（手修正区間のみ内部を0.5秒刻み）＝144区間で数分かかっていた確認を短縮
- 保存先は記憶（SETTINGS.hlOutDir）。中止ボタンあり
- **自分のキャラ表示（バッジ）**（ユーザー要望「生成された動画で自分がどのキャラか分かるように」2026-09-02）:
  **バッジは「自分：」＋VS画面の自分側カードのキャラ画像だけ**（名前は出さない・味方の情報も持たない。ユーザー指定 2026-09-02）。
  試合ヘッダに画像と「表示」チェック。ダブルスは myRowFromSigs で自分の行を決め（決まらなければ上の行を仮置き＋警告）、
  2行の画像をラジオで選び直せる。**ダブルスのアイコン枠(118x64)の切り抜きは x+12〜112 の 100x64**（2026-09-21）:
  顔は枠の左寄り〜中央にある（6試合の実測: パタパタ x28〜77・キャサリン 0〜55・クリボー 15〜100・マリオ 20〜90・ヨッシー 10〜95。
  右端 ~20px はラケットや羽だけ）。旧実装は「右寄せ」と決め打ちして右端の正方形(x50〜118)を切っていたため、
  **パタパタの顔が半分・キャサリンは顔が消えていた**（ユーザー指摘 2026-09-21・ダイジェスト冒頭のバッジ）。左端 ~12px はランク表示(S+/S-)が食い込む。
  バッジは renderer の canvas で透過PNGに描く（出力の高さに合わせて拡縮・システムフォント）→
  `hl-save-png` で一時フォルダへ → ffmpeg の `-loop 1 -i badge.png` + `overlay`（上中央 y=2.5%）。
  「最初の3秒/5秒」は末尾0.5秒で alpha フェード、「ずっと」は常時。drawtext は使わない（日本語フォント指定が環境依存になる）

## 対戦相手の表示とファイル名（2026-09-21・ユーザー要望「この試合は誰とだったかがぱっと見分かるように」）

動画にはプレイヤー名を入れない前提（バッジは自分のキャラ画像だけ）を崩さず、**一覧とファイル名**で分かるようにした。
- `detectMyChar` と同じ VS フレームで `readWho`: VS カード全体（x268〜1652・y845〜997・シングルス/ダブルス共通）の画像 `w.vsCard` と、
  相手/左列の名前・キャラ `w.who`。名前は戦績CSV解析と同じ2段（`nameFromSig` → `ocrName`・index.html のグローバル）、
  キャラは `matchIconCard`（シングルス vsIcons）/ `matchIconCardAround`（ダブルス dblIcons）で 0.8 以上のみ。読めなければ空
- 表示 `whoHtml`: 試合ヘッダの下に VS カード画像（高さ72px＝名前が読める大きさ）＋「相手: 名前・名前　味方: 名前」。
  読めなかった人はキャラ名に「(キャラ)」を添えて名前と区別する。区間調整モーダルの見出しにも「vs 相手名」
- `whoOf`: 同じ録画の戦績CSV解析が済んでいれば `matches`（`m.video === HL.file.name` かつ `_vsT0` が VS 時刻±3秒）の
  oppName/opp2Name/partnerName（手修正込み）を優先。ダブルスの味方は「自分の行」の反対（ラジオで選び直すと追従）
- ファイル名 `vsTag`: `_vs相手1・相手2`（読めた名前だけ・キャラ名では代用しない＝「vsクリボー」が人名に見える・40字まで・safeName）。
  `録画名_試合n_vs相手名_Pkk_…` / `録画名_試合n_vs相手名_ダイジェスト.mp4` / 試合ごと `録画名_試合n_vs相手名.mp4`。
  全試合を1本にしたときは付けない。チェック「ファイル名に相手の名前を入れる」（SETTINGS.hlOppName・既定ON）で外せる
- ブラウザ検証: `samples/tmp/hltest-dbl.mp4`（2026-09-21 04-08-15 の m1/m5/m6 の VS＋レートパネルを継いだ 2分9秒・git管理外）で
  3試合とも相手・味方の名前が読め（ユーザー辞書 %APPDATA%\SENSEKI SCAN\*.json を localStorage の sc_* に写して）、
  m6 は自分の行=下も正しく判定。シングルスは `hltest-sgl.mp4`（15-18-15 の冒頭）

### ダブルスで「誰が決めたか」（自分/味方・相手1/相手2）は未対応
ユーザー要望（2026-09-21）だが、**画面にその情報が出ない**: コーナーHUD・ポイント間バナー・ジュゲムの吹き出し（「ナイスアングル!」等）・
得点直後のカメラ（自チーム2人が並んで映る）のどれにも決めた人の印は無い（04-08-15 の 195秒付近を 12fps で確認）。
決めた人＝「勝った側で最後に打った人」なので、ラリー解析（Phase C）の打点検出＋その位置に居るキャラの特定が要る。
いまの Phase C は自分側（近い側）の打点が弱く、ダブルス（4人）は未検証。同キャラ同士のチーム（ミラー）は色でも分けられない。
→ Phase C が実用になるまで保留。つなぎとして区間調整モーダルで手で付ける案（自分/味方トグル→一覧とファイル名に反映）は提案のみ

## 既知の限界・今後
- ②の始点は「終端−N秒」の固定。要望の「ラリー状況が分かる区切り」（打点や着弾に合わせる）は Phase C のボール追跡が
  実用化してから。いまは手修正で対応
- 1ポイント目の①にウォームアップが含まれる
- ダブルスで自分/味方のどちらが決めたポイントかは出せない（上記）
- 相手の名前が**コート上に**出る画面は無い前提。新しい演出で名前が出る画面が見つかったら `nameRisk` に条件を足す
- 戦績CSVの解析中はハイライト解析を始められない（同時デコードで両方遅くなるため）
