# ハイライト生成（得点シーンの自動切り抜き）— 設計と検証

初版 2026-09-02（v0.4.0）。**この機能を触るときは先にこのファイルを読む。**
ユーザー要望: 読み込んだ動画から ①サーブ開始〜得点までの区間 ②得点直前の数秒 を自動で切り抜き、
気に入らなければ手で直せて、②は1試合単位で繋げたダイジェストも出せること。
**Xに投稿するときプレイヤー名が映らないように**、名前が載る画面（ポイント間のスコアバナー等）は必ずカットする。

## 構成

| ファイル | 役割 |
|---|---|
| `app/renderer/rally.js` | Phase A（得点HUD→ポイント境界）。`tools/rally.js` の同梱版。readSide が領域セットを受け取れる |
| `app/renderer/highlight.js` | 認識ロジック。試合窓 → HUD走査 → ポイント化（純粋関数）→ 切り抜き区間 → 名前ガード |
| `app/renderer/hl-ui.js` | UI（パネル・一覧・区間調整モーダル・書き出し）。index.html のメインスクリプトの後に読み込む |
| `app/main.js` | `hl-*` IPC。同梱 ffmpeg で切り抜き（再エンコード）と連結（copy） |
| `tools/highlight-node.js` | ヘッドレス検証。renderer の3ファイルをそのまま vm に載せ、ffmpeg の生フレームで readFrame→buildPoints |

ffmpeg は npm の `ffmpeg-static`（gyan.dev essentials 6.1.1・libx264/aac 入り・GPL）。
`build.asarUnpack` で asar の外に出し、main.js が `app.asar.unpacked` に読み替える。
**npm 12 は依存の install script を既定でブロックする**ため、`npm install` だけでは exe が落ちてこない。
`npm run dist` の前に `predist` が存在確認して止める → `node node_modules/ffmpeg-static/install.js` で取得。

## 認識の流れ

1. **試合窓**: `V.scan`（1秒刻み・戦績CSV解析と同じ）→ レート検証ゲート（`gateRatings`・index.html から関数化）→
   `Highlight.matchWindows`: vs → (winner) → rating で1窓。groupMatches と同じく「前試合が閉じる前の vs は無視」。
   レートパネルの無い録画（COM戦）は1窓に複数試合が入るが、次段の**得点リセット**で分かれる。
   戦績CSV解析が済んだファイルはシーン走査を `SCENE_CACHE` から再利用する。
2. **HUD走査**: 窓内を 0.5秒刻みでシークし `readFrame`（コーナーHUD + classify + ポイント間バナー）。
3. **ポイント化** `buildPoints`（純粋関数）: HUD点灯セグメントを作り、「直前に読めた得点」と「次に読めた得点」を
   比べる（数字未描画の一瞬のセグメントは飛ばす）。
   - 得点が動いた → ポイント（勝者は `Rally.whoScored`）
   - 総得点が減った（6-4 → 0-0）→ 試合の切り替わり。直前の状態から**最終ポイントの勝者**を一意に決める
     （通常: 片側だけ6ならその側 / デュース: Adv.側）。窓の最後のセグメントも同じ扱い
   - 同じ得点のまま短い消灯（≤4.5秒・リプレイ等）→ 同じポイントの続き（始点を維持）
4. **境界の精密化**: 消灯開始・復帰を二分探索で 1/30秒まで詰める（消灯開始＝バナー出現の直前なので精度が要）。
5. **切り抜き区間** `clipRanges`: 終端 = 消灯 − 0.15秒。① 復帰〜終端 / ② max(復帰, 終端 − N秒)〜終端（N既定5・2〜20）。
6. **名前ガード** `guardRange`（書き出し直前・既定ON）: 区間の末尾/先頭/内部(0.25秒刻み)を読み、
   バナー・VS画面・勝敗パネルが映るフレームがあれば区間を詰める。手修正で終端を消灯の後ろに置いても、ここで手前に戻る。

### プレイヤー名が映る画面（＝映してはいけない）
- **ポイント間の黒いスコアバナー**（画面下中央・`名前 [icon] n - m [icon] 名前`・ダブルスは2行）。
  実測（10-44-35・30fps）: コーナーHUD消灯 297.133 → バナー出現 **297.233（+0.10秒）** → 消灯 298.8 → HUD復帰 299.87。
  検出はバナーのピップ（deuce-pips.md: 左ピル x667-848 / 右 x1071-1252, y977-1014）を `Rally.readSide` で読む（present のみ使う）。
- VS画面 / 勝敗パネル（classify の vs / winner）。
- 試合中の HUD・ショット名の吹き出し・SMASH 等のラベルには名前は無い（実フレームで確認）。

## 設計を縛る実測（2026-09-02 ヘッドレス検証）

- **砂コートはHUD消灯中でも7スロットが全部 'Y' に読める** → readSide の present に **ピル地の占有率 fill ≥ 0.25** を追加
  （旧: スロット構成だけ）。修正前は「7-7」の偽HUDが多発しポイントが崩壊。
  実測 fill: 点灯時 min 0.412〜0.421（p50 0.44）/ 消灯時は 0.000 が大半（フィーバーの演出で 0.9〜1.0 になる
  フレームがあるが、スロット条件で落ちる）。`tools/rally.js` にも同じ修正を入れた
- **数字未描画（numW<30）の一瞬のセグメント**が境界に挟まると、前後比較が「読めない」で切れて
  ポイントを取りこぼす → 「直前に読めた状態」との比較に変更（上記3）
- ウォームアップ（0-0）→ 1ポイント目は **HUDが消えない**（10-44-35: 25.5〜46.5 が連続点灯）→ 1ポイント目の
  ①区間はウォームアップを含む。②は末尾N秒なので影響なし。必要なら手修正
- フィーバー最終ポイントで HUD が 32秒点灯し続けた例（00-08-01 g3）。演出込みだが害はない

### 検証結果（`node tools/highlight-node.js <video> [t0 t1] --fps 2`）

| 素材 | 結果 |
|---|---|
| 10-44-35（1080p60・砂・クラシックS・3試合） | **7-1 / 7-2 / 7-5** の全ポイント検出。偽ポイント0。各消灯区間でバナー検出（3サンプル≒1.5秒） |
| 00-08-01（1080p60・フィーバーS・120〜720秒） | 4-7 / 2-7 / 7-4 / 6-6→デュース(窓端)。デュース遷移も正読 |

いずれも「1試合＝勝者7点」で整合。試合の切り替わり（得点リセット）も全件正しく分かれた。

## 書き出し（main.js `hl-cut` / `hl-concat`）

```
ffmpeg -ss S -i IN -t D -map 0:v:0 -map 0:a:0? [-vf crop=w:h:x:y,scale=-2:'min(ih,1080)']
  -c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p -c:a aac -b:a 160k -ar 48000
  -movflags +faststart -avoid_negative_ts make_zero -y OUT
```
- `-ss` を `-i` の前に置いて再エンコード → キーフレーム位置に関係なく**フレーム単位で正確**（copy だと最大2秒ずれる）
- 実測: 1080p60 の5秒クリップ 1.4秒（この機での libx264 veryfast）。NVENC も同梱ビルドで使えるが、
  全ユーザーで同じ結果にするため未採用
- 「ゲーム画面の位置」（SETTINGS.gameRect）があれば crop、1440p以上は 1080p へ縮小（チェックで切替）
- ダイジェスト: 同一設定で切った②クリップを concat demuxer で `-c copy` 連結（一時フォルダに切ってから連結し、削除）
- ファイル名: `録画名_試合n_Pkk_スコア_自分|相手[_ラリー全体].mp4` / `録画名_試合n_ダイジェスト.mp4`
- 動画のパスは preload の `webUtils.getPathForFile`（Electron 32+ で File.path は廃止）

## UI（hl-ui.js）

- 「ハイライト生成」パネル: 録画を選ぶ／直近の解析ファイルで作る／パネルへのドロップ
- 一覧: 試合ごとにポイント行（サムネ・P番号・自分/相手・スコア遷移・マッチ決定・②/①区間・手修正マーク）。
  既定は「自分の得点だけを選ぶ」ON。得点前の秒数は 2〜20 秒
- 区間の調整モーダル: 切り出しプレビュー（gameRect を CSS で再現）・タイムライン（緑=HUD点灯・赤=消灯後＝名前が映る）・
  ハンドルのドラッグ・±1s/±0.1s・区間再生・開始/終了をここに・自動に戻す・Space/←/→/Esc。
  終端を消灯より後ろに置くと警告（ガードONなら書き出し時に詰める）
- 書き出し: ②個別 / ダイジェスト（試合ごと連結） / ①個別。保存先は記憶（SETTINGS.hlOutDir）。進捗と中止

## 既知の限界・今後
- ②の始点は「終端−N秒」の固定。要望の「ラリー状況が分かる区切り」（打点や着弾に合わせる）は Phase C のボール追跡が
  実用化してから。いまは手修正で対応
- 1ポイント目の①にウォームアップが含まれる
- 相手の名前が**コート上に**出る画面は無い前提。新しい演出で名前が出る画面が見つかったら `nameRisk` に条件を足す
- 戦績CSVの解析中はハイライト解析を始められない（同時デコードで両方遅くなるため）
