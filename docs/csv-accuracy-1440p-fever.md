2026-08-26 未明実施。素材 = `samples/2026-08-25 23-10-02.mp4`（2560x1440 60fps・33分・OBS元録画）。
正解 = SENSEKI FEVER 登録の8試合（録画開始前に始まった1試合を含む・service_role照会＋疑義セルは全て動画目視で確定）。

### コア項目の誤り内訳（すべて実測・目視確定）
1. **ノコノコ:赤 ↔ :青**（0.96・無警告）— 甲羅色は16x16アイコンで数セルしかなく色違いに弱い。唯一の無警告誤り
2. ボスパックン → パタパタ（0.46・フラグ）— **ボスパックンは辞書未収穫**
3. パタパタ:青 → ハナチャン（0.74・フラグ）— **パタパタ:青も未収穫**
4. 最終スコア **4→6 誤読 ×2**（フラグ付き）— 720pクラシックでも1件。lightink の「4」が
   これで3例連続して「6」に化けており、次の数字読み改善の最優先ターゲット

## ラケットバナー辞書の収穫（同夜実施・適用済み）

### 手順が重要（side帰属×正解ラベルでの収穫は失敗する）
最初に「FVゲージのside帰属 × SENSEKI FEVERの正解ラケット」でラベル付けしたら、
**side帰属の誤り（m2で4件中2件）がテンプレを汚染**し、hold-out 28件中13件誤りで破綻した。
正しい手順は **バナープロファイルをクラスタリング（相互xcorr≥0.95）→ クラスタ代表を目視ラベル**。
40イベントが7クラスタにきれいに分離し、目視で以下が確定:

| クラスタ | 正体 | 扱い |
|---|---|---|
| 27件 | フリーズショット | フリーズラケット（GT×sideの誤ラベル2件もここに吸収） |
| 2件 | ブラックホールショット | ブラックホールラケット |
| 3件 | アイスショット | アイスラケット |
| 4件 | **スターブースト**（表記がショットでない） | スターラケット |
| 2件 | バナナショット | バナナラケット |
| 1件 | フリーズのスライドイン途中 | 除外（部分バナー） |
| 1件 | **偽バナー: Adv.スコアHUDをfindBannerが誤検出** | 除外（旧サンボ0.898誤答の正体） |

hold-out検証（テンプレ10本／検証27件）: **27/27 全正解・閾値未満0**。racketBanners 64→74本。

### decide() の優勢判定（同時に適用）
side帰属誤りが少数派の誤名を混ぜるため、「2種類=ハテナ」を
**「最多が2件以上かつ2番手の2倍以上なら最多を採用」**に変更。本物のハテナ（ランダム発動）は
ほぼ均等に割れるので優勢判定にかからない。

### 収穫後のラケット判定（40イベントで忠実にシミュレート）
**13/16 サイド一致**（旧: 名前が付いたのは誤り2件のみ）。残り3件は
m2自分=null（自分のバナー2件が相手に誤帰属されたため）/ m2相手=ハテナ（同原因の均等割れ）/
m8相手=null（**ドロドロラケットのみ side付きバナーが1件も無く未収穫**）— いずれもフラグ付きで確認画面に出る。

## 残課題（優先順）
1. **lightink の「4」→「6」誤読**（3例連続・フラグは立つが最頻出の数字誤り）
2. **FVゲージのside帰属の精度**（実測で誤り例あり。dropL/dropRのマージンを racketEvents に保存して
   確信度の低い帰属を捨てる／バナー名が自分のラケットと一致しない場合の再帰属 などが候補）
3. 未収穫: **ドロドロラケット**・**ボスパックン**・**パタパタ:青**・色違いの甲羅（ノコノコ赤/青の判別）
4. findBanner が Adv. スコアHUDを誤検出する件（今回は優勢判定で無害化されたが根は残る）
