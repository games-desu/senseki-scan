## 判明した事実（2026-08-27訂正: ユーザー確認によりモード形式はいつもと同じランクマッチ）

当初「別系統の画面セット/モード形式の違い」と推定したが**誤り**。正しくは「昔から存在する画面バリエーション
（表示タイミング）をどのフレームで掴むか」の取りこぼし問題。解像度/画質も原因ではない
（FHD・約6Mbps=過去の高精度検証動画と同等）。観測した画面:

1. **試合開始時の画面下部バナー**（これが標準のVS表示。シングルスの認識領域はこの配置と整合しており#9-18は高精度）
   （左チーム=名前プレート+小アイコン・右チーム=小アイコン+名前プレート。シングルスは各1人）。
   名前プレート位置は従来の dNameL1/dNameR1 とほぼ同座標 → myname照合・名前クロップは機能する。
   **小アイコンは従来のアイコン領域とズレる+サイズが小さい** → キャラ誤認識の主因
   （ダブルスの味方/相手2はconf 0.00、自分/相手1も部分重なりで誤る）。
2. **ランク付きレートパネル**（試合直後の金色パネル。別途、次試合待ち画面に「クラシック（ダブルス）2,545」型のシンプル表示もあり、レート窓はどちらも classify=rating になる）: S+/A+ランク・世界ランキング・「レーティング 3,291」（桁区切りカンマ付き）
   ・ゲージ付きの金色パネル。**1枚の中で「変動前→カウントアニメ→変動後」と遷移**し、
   静止時間はプレイヤーのスキップ操作次第。
3. **勝敗パネルの傾き演出**: スコアパネルが斜めに傾いて表示される時間帯がある
   （シングルス#17: 画面上7-4なのに8-6と誤読・ダブルス#1-4: 読めずnull）。

## ダブルスVSバナーのキャラ認識 → **解決済み（2026-08-27）**

- 「conf全試合0.00」の正体は**表示バグ**（m.partnerCharConf / m.opp2CharConf の代入漏れ → ??0 で常に0.00表示）。認識自体は動いておりflagも正しかった。修正済み。
- 実際の精度問題は「バナーのキャラ絵がアニメでポーズ変化し単一テンプレでは不安定」＋辞書の薄さ。
  6試合×2フレームから目視確定ラベル（バナー帯画像でGT整合を確認してから）で19テンプレ収穫 → dblIcons 35→54。

  残るは#1のレート変動前のみ（バッチ先頭でRATE_CHAINが無く、画面からも安定値が取れないケース。フラグ付き手入力）。
- 副産物の発見: **試合中のスコアUI（ゲームカウント表示）が classify で vs に誤分類されることがある**
  （レイアウトがVSバナーと同構造のため）。今回の解析では実害なし（アイコン配置も同じで読める・playedAtもGT一致）だが、

## 勝敗パネル「傾き」問題 → **解決済み（2026-08-27）**

- ストリップ実測（#17のパネル表示区間を0.25s刻み）: パネルは**約1.5秒間ほぼ正面で静止**しており、
  傾きは出入りアニメの一瞬だけ。つまり主因は傾きではなく**旧w1digit塊読みがこの動画の描画で崩れた**こと
  （枠外の暗部と融合した塊がpanelFontの8/6テンプレに誤マッチ）。
- 対処: **スコア読みをシングルス/ダブルス完全統一** — 領域=dw1digit/dw2digit（枠内クリーン）・
  書体=panelFont収穫分∪ratingFont・採用=conf>=0.5の値最大・locateWinnerもdw領域。
  旧w1digit塊読みとpanelFont塊テンプレはスコア読みから引退（panelIconsによる勝敗行アイコン照合は現行のまま）。
- 検証: #17/#18が**7-4（GT一致・conf0.98-1.0）に根治**・720p旧検証動画で8-6をGT通り正読（退行なし）・
