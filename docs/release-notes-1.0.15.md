# v1.0.15（2026-11-02）：回線切れで終わった試合の次の試合に、前の試合の対戦相手が付く

## 症状
ぴんやさん報告（録画 `20261018_error.mp4`・3分25秒・配信レイアウト rect 13,101,1404,789）。
1試合目（VS画面 8秒・相手マリオ）が相手の回線切れでレート画面が出ないまま終わり、続く2試合目（VS画面 88秒・相手カロン 7-5 勝ち）が
**相手マリオ**として出た。ログには「VS画面2回に対し成立した試合が1件」の警告。

## 原因
`groupMatches`（vision.js）は「前の試合が rating で閉じるまでの vs は試合中UIの誤分類」として読み飛ばす。
回線切れの試合には rating が来ないので、2試合目の本物の VS 画面まで捨てられ、1試合目の vs に2試合目の winner/rating が付いた。
ハイライト生成の `matchWindows`（highlight.js）も同じ規則で、2試合が1つの窓に入り、自分のキャラ・対戦相手・ファイル名の「vs相手名」が1試合目の VS 画面から取られていた。

## 修正
- 読み飛ばす vs を捨てずに `vsLater` として残す（groupMatches / matchWindows）
- 本物の VS 画面は左上にコート名が出る。`vsCourtReadable`（index.html）でコート名の照合スコア 0.85 以上のものだけを本物とみなす
  - 実測（ぴんやさん録画を1秒刻み）: 本物の VS 画面 0.946〜0.969 / それ以外の全フレーム 最大 0.654
- 戦績CSV: `pickVs` が読めた最後の vs を試合の起点にし、それより前の winner は捨てる。束ねた vs は「VS画面n回に対し」の警告から差し引く
- ハイライト: `splitAtLaterVs`（hl-ui.js）が読めた vs ごとに窓を分ける。回線切れの試合は最終ポイントが無い（finalWinner=null）ので途中までのポイントだけ残る
- どちらもログに「{0}秒のVS画面の試合はレート画面が出ないまま終わっています（回線切れ等）。{1}秒のVS画面を次の試合の始まりとして使います」
