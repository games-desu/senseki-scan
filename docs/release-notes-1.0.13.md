# v1.0.13（2026-10-04）：ファイル名の日時の誤読

## 症状
Twitch アーカイブをダウンロードした録画 `2890752604-584766680-<uuid>.mp4` を解析すると、試合日時が **9077-02-06** になった。
SENSEKI FEVER に取り込んだ28件がすべて未来の日付で登録された（本番データは VOD 開始 2026-10-03T14:08:49Z 基準で手修正済み）。

## 原因
`parseStartTime`（app/renderer/index.html）の Switch 本体形式 `(\d{4})(\d{2})(\d{2})[_-]?(\d{2})(\d{2})(\d{2})` に桁境界が無く、
`2890752604-584766680` の途中 `9075 26 04 - 58 47 66` に一致した。`new Date` は範囲外を黙って繰り上げる（26月→翌々年2月）ので 9077年になり、
source='name' 扱いのため要確認も付かなかった。

## 修正
- 4つのパターンすべてに `(?<!\d)` / `(?!\d)` の桁境界（Switch 形式は末尾2桁の百分の一秒を任意で許す）
- 年 2000〜2099・秒 0〜59、かつ Date を組み立て直して月日時分が一致したものだけ採る（2月30日・25時なども不採用）
- 同じ形が複数あれば、ありえる日時になる最初のものを採る（matchAll）
- どれも採れなければ従来どおり 更新日時−長さ（source='mtime'＝要確認）

## 検証
- 単体ケース: Twitch VOD 名→mtime／OBS 2形式・Switch 2形式・和文・日付だけ→従来どおり／13月・2月30日・前に数字が続く名前→不採用
- samples/・Videos・Downloads の動画名49件で旧版と比較: 変わったのは Twitch VOD 3件だけ（9000年台→mtime）。他46件は完全一致
- 読み取り（vision.js・CSV 生成）は触っていないので動画の回帰は省略
