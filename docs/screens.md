## 数字フォントの読み方（重要な知見）

- レート数字は**縁取り同士が接触**するため、暗い縁取り（darkink）では分割不能
- **縁取り内側の白い塗り（fillink: 輝度>215 かつ 彩度<15）**なら数字ごとに孤立 → 列射影で分割可
- **分割は連結成分(CC)ベース**（列射影は不可）。理由: ①コンマが数字の懐に横位置で重なり縦の谷では分離不能 ②プロポーショナルで縁取り同士が接触。塗り同士は連結しないのでCCで確実に分かれる
- CC前に**縦3px未満の画素を除去**（パネル縁の細い水平線がグリフ同士を橋渡しして1成分に融合するため）
- エロージョン後の数字の塗りの実高はクロップ高の**約36%**（旧45pxは細線混入の嵩増しだった）。フィルタ: 数字=高さ25〜85%・コンマ=高さ30%以下かつ下半分・右端細片と縦光は除去
- 収穫時のラベル対応は**x順でなくクラス別**（数字箱/コンマ箱を形状分類して数字ラベルを数字箱にx順で割当）。コンマは数字の懐に入るためx順が揺れる
- **要注意教訓**: 「期待数に合わせて最も幅広の箱を割る」ヒューリスティックは、融合箱が普通の数字と同幅のケースで別の箱を割り**ラベルがズレてテンプレートが汚染**される。形状パターン検証つきの分割のみ許可
- レートパネルはフェードイン中グリフが拡大されて歪む → 数値は「連続2回の読みが一致」した値のみ採用（analyzer.readNumberAt）
- スコアは**デュースで8点以上になりうる**（実例: 8-6）。勝者スコア=7固定の仮定は禁止。Winnerパネルの勝者行も固定でない（上下どちらもある）
- レートパネルの数値は**カウントアップ演出**: 表示直後=rating_before → 2〜4秒後に安定=rating_after
  - before = 窓先頭+0.4/+0.9秒の2回読みで一致確認
  - after = 窓末尾-1.0/-0.4秒の2回読みで一致確認
