## 誤りの構造（4つに分解できる）

### 1. ダブルスアイコン辞書（dblIcons=19本）の決定的不足 — 誤りの本体（22セル）
今回の正解に出た キャラのうち **デイジー・ヨッシー:水色・ゲッソー・ドンキーコング・パックンフラワー・
ガボン・キャサリン・ベビィマリオ・ベビィワリオ が未収穫**。ほぼフラグは立つが、
未収穫キャラが「辞書内の似た何か」に化けて conf≥0.8 に達した**無警告誤りが5件**
（ノコノコ甲羅色 青/赤・チコ/ロゼッタ・マリオ/ロゼッタ・チコ/マリオ・クリボー/ハナチャン）。
→ 対処はフィーバーで確立した収穫フロー（この動画から目視ラベルで一括収穫できる）。
　ダブルスは opp1/opp2 の行順の突き合わせに注意。

### 2. ダブルスの winner パネルが classify に一度もヒットしない（新発見・要コード修正）
35分のスキャンで **winner窓が0件**（シングルスでは毎試合出る）。逆走査＋locateWinner の救済で
6/8試合はスコアを拾えたが、m5/m7 は完全に取り逃し（スコア/勝敗が空・フラグ付き）。
ダブルスの勝敗パネルはアイコンが2個並ぶため黄色ハイライトの検査領域(160-176,78-98)@192 が
ずれている可能性が高い。実フレームでの領域実測が必要。

### 3. 最終スコア「4→6」誤読が**ついに無警告で発生**（m3・通算5例目）
720p×1・1440p×4。今回は conf が閾値を超えてフラグも立たなかった。
lightink の「4」テンプレ対策が数字読みの最優先課題であることが確定。

### 4. 孤児rating警告の誤報4件 → 閾値を60秒に拡大して対処済み
ダブルスでは試合後の画面遷移でレートパネルが 11〜42秒間隔で複数回出る。
30秒ルールでは42秒の分割が誤報になった。60秒に拡大（本物のDK戦は225秒差なので検知力は不変）。
※今回の実行はページ未リロードのため旧ロジック（誤報4件）で走った点に注意。

## アルバム/ホーム画面対策（2026-08-26 追加・v0.2.2）

ユーザーは録画中にホーム→アルバムでスクショ/動画を見返すことがある（本動画の 695〜745秒に実例:
**直前の試合の再生映像がほぼ全画面で表示**され、下端に Switch の操作バーだけが乗る）。
再生中の映像に VS/勝敗/レートパネルが写るとスキャンが誤爆して幻の試合を作るリスクがある
（今回はラリー映像しか再生されなかったため実害ゼロ＝運が良かっただけ）。

**対策**: 操作バーの凡例（+全画面表示 Y再生 X消去 Bもどる Aメニュー・固定UI）を
白チャンネルNCCのテンプレ照合で検出（albumBar セット・実測 バー表示中 0.995〜0.998 /
ライブ側の最悪値 0.61・閾値 0.8）。scan で vs/winner/rating と分類されたフレームにバーが
出ていたら 'album' に付け替えて解析対象外にし、UIログに除外区間を表示する。

**残存リスク（仕様として明記）**: 「全画面表示」中や操作バーが自動で消えている間の再生映像は
画素上ライブと区別不能。ただし ①Switchの動画クリップは短くVS→レートの完全な幻試合を構成しにくい
②幻のレートパネルは孤児rating警告で可視化 ③レート連鎖検証で不整合が出る、の三重の網で実害を抑える。
