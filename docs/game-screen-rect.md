# ゲーム画面の位置指定（配信レイアウト対応）

2026-09-01 実装（v0.3.15・未リリース）。ユーザー要望「配信している人は必ずしも画面いっぱいに
ゲームが映っているわけではない」への対応。

## 何をしているか

- 「フレームの中でゲーム画面が占める範囲」を**割合 `{rx, ry, rw, rh}`（0〜1）**で持つ
  （`SETTINGS.gameRect` → `userData/settings.json`）
- vision.js に `setSourceRect(r)` / `getSourceRect()` / `srcRect(video)` を追加し、
  **切り出しは全部そこ基準**にした
  - vision.js: `frameToData` / `cropRegion`
  - index.html: `cropDataUrl` / `frameJpeg` / `regionJpeg`
- 認識ロジック側の座標はこれまでどおり **1920x1080基準のまま**。`cropRegion` が
  `kx = srcRect.w / 1920`, `ky = srcRect.h / 1080` で吸収するので、REGIONS も照合も無改造
- 割合で持つ理由: 同じOBSレイアウトなら1080p録画でも1440p録画でも同じ設定が使い回せる
- 未設定（null）＝全画面＝従来と完全に同じ挙動

## UI（「ゲーム画面の位置」→「変更…」）

| 方法 | 使いどころ |
|---|---|
| **数値(px)入力** | 一番正確。OBSのゲームソースの位置・サイズをそのまま入れる |
| **自動検出** | 数値が分からないとき。等倍で走らせるので1px単位で当たる |
| **ドラッグ選択** | ざっくり合わせる。`16:9に合わせる`ONで比率は自動で丸める |

右側に「切り出し結果」プレビュー（この絵がそのまま解析にかかる）と、実ピクセルサイズ・
縦横比・警告（1280px未満／16:9から外れている）を出す。設定は**全ファイル共通**。

## 自動検出のしくみ

動画から8フレームを等間隔にサンプリングし、画素ごとの輝度レンジ(max-min)を取る。
**時間方向に動いている画素の範囲＝ゲーム画面**（静止した枠・ロゴ・チャット欄は動かない）。
列/行に投影し、「正の値の中央値の30%」をしきい値にして最長ランを取る。

- **等倍（1920x1080のまま）で走らせるのが必須**。縮小グリッド(192x108)でやると10px単位に
  丸まり、それだけで精度が壊れる（下記）
- 動くカメラ映像が端にあっても、投影のしきい値で落ちる（合成テストで実証済み）

## 精度の勘所: **ずれは解像度低下よりずっと効く**

合成テスト（1920x1080のフレームにゲームを1408x792＝横73%で配置）での実測:

| 指定 | コート | 自分キャラ | 相手キャラ |
|---|---|---|---|
| 全画面（元動画そのもの） | 0.984 | 0.999 | 0.963 |
| **正確な矩形** (24,180 1408x792) | 0.988 | 0.993 | 0.957 |
| **4pxずれた矩形** (20,180 1404x790) | **0.835** | **0.776** | **0.716** |

- 73%に縮んだこと自体の損失は**ほぼゼロ**
- たった4pxのずれで、コートは要確認しきい値(0.85)を、キャラは(0.80)を割る
- → **1px単位で合わせることが全て**。だから自動検出は等倍で行い、数値入力欄を用意した

正確な矩形での全項目テスト（全画面での結果と同じ）:
scan = vs@10-13 / winner@142-144 ・ コート0.988 ・ キャラ0.993/0.957 ・
勝敗パネル t=144.75 row1 ・ パネルアイコン0.993/0.930 ・ 勝者スコア7 ・
ラケット4件すべて 0.966〜0.989 で正解（ドロドロ2・ドッスン2）。

## テスト素材の作り方

`samples/stream-layout-test.mp4`（gitignore対象）。CapCut同梱ffmpegで生成:

```
ffmpeg -y -f lavfi -t 150 -i color=c=0x0d1117:s=1920x1080:r=30 -i "2026-08-31 23-55-06.mp4" \
 -filter_complex "[1:v]scale=1408:792[game];[1:v]scale=336:189,hue=s=0.3[cam];\
[0:v]drawbox=x=1470:y=250:w=430:h=760:color=0x161b22@1:t=fill,\
drawbox=x=1470:y=250:w=430:h=48:color=0x30363d@1:t=fill,\
drawbox=x=0:y=0:w=1920:h=170:color=0x161b22@1:t=fill[bg];\
[bg][game]overlay=x=24:y=180[t1];[t1][cam]overlay=x=1500:y=20[out]" \
 -map "[out]" -c:v h264_nvenc -preset p5 -rc vbr -b:v 9M -maxrate 12M -bufsize 18M \
 -pix_fmt yuv420p -movflags +faststart stream-layout-test.mp4
```

ffmpeg の場所は `C:\Program Files\CapCut\Apps\<最新版>\ffmpeg.exe`（NVENC専用ビルド）。
正解の矩形は **x=24, y=180, w=1408, h=792**。カメラ相当が右上で動くので自動検出の耐性も見られる。

## 気をつける点

- 設定は**全ファイル共通**。全画面録画を読ませるときは「全画面に戻す」こと
  （位置指定なしでレイアウト録画を読ませるとイベント0件になるので、
   **VS画面が1件も無いときは警告で気づけるようにしてある**）
- ゲーム画面が横1280px未満になると文字が小さくなり精度が落ちる（警告を出す）
- 16:9から外れた指定は基本的に間違い（ゲーム画面は必ず16:9）→ 警告を出す
