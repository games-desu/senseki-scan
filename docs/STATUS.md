### v0.3.14(公開済み 2026-08-31・名前の文字辞書=実質OCR + ダブルス自分行判定の刷新)
「初対戦の相手でも名前が入る」ようにするため、**ユーザーが入力した名前を教師に文字辞書を育てる**方式を追加。
キャラ/コートの教えるサイクルを文字に適用したもの。

- **学習**: CSV保存時、手入力/修正した名前について、名前画像を**入力された文字数に合わせて分割**し
  1文字ずつ収穫する(userData/chars-user.json・1文字3枚まで・酷似ncc>=0.99は追加しない)。
  分割は「ストローク塊を隙間の狭い順に併合して文字数に合わせる」方式＝ラベルのズレが起きない。
  塊が足りない(文字同士がくっついている)場合は収穫を見送る。実測 22/23プレートで収穫成功
  (見送りは詰まった英大文字 MTZA のみ)
- **読み取り**: 名前画像に一致する過去の名前が無いとき、文字辞書で読む(V.readName)。
  1文字=1〜3塊としてDPで最良の区切りを選ぶ＝「け」「は」「ぬ」の縦棒や濁点が別塊でも正しく束ねる
  (塊をそのまま1文字とみなす方式は23プレート中14しか当たらない)
- **1文字は16x16 + セル重ね0.25**。24x24だと1セル≒1pxで平滑化が効かず、枠が1px違うだけで
  同じ字のNCCが0.98→0.77に落ちる(「り」の実例)。重ねを入れて同字1位正解45/45
- **しきい値0.90**: 実測で「辞書に無い文字の最良スコアは最大0.897」→ 知らない字は読まずに諦める
- **実測(同素材23プレート)**
  - 文字辞書OCRの leave-one-at-plate-out: **完全一致8 / 不一致0 / 読めず14**(読めず=その名前の字が辞書に無い)
  - 全字を学習済みで読み直し: **22/23完全一致・不一致0**(辞書81枚/58文字)
  - 画像シグネチャ照合(v0.3.13)はリファクタ後も 正解8/誤り0/取りこぼし0/正しい棄権15 で退行なし
- 自動入力された名前は辞書に収穫しない設計を維持 → **OCRの誤りが自分を強化することはない**。
  手で直せばその字が正しいラベルで入る(自己修復)
- **ダブルスの「自分の行」判定も刷新**（同v0.3.14）
  - 旧方式は欄全体のtextVecを同梱mynameテンプレと照合。実測4試合とも正解だったが
    **差が0.021〜0.064しかなく、外れた側が0.936〜0.979**（同じ3文字の味方名と紙一重）。
    さらに同梱テンプレは開発者の名前なので**他の利用者には最初から効かない**
  - 新方式: **シングルスVS画面の自分側プレート(R.myname)からシグネチャを自動学習**し
    (myname-user.json・直近3枚)、ダブルスの左列2行と照合して自分の行を決める。
    ユーザーが名前を入力する必要はなく、誰の環境でも自動で成立する
  - 実測: 自分=0.938〜0.949 / 味方=0.000〜0.231（左列は右寄せ・シングルスは左寄せ・欄サイズも
    違うが、インク枠の正規化で一致する）。処理順を再現した通し確認でも4/4正解
  - 自分の名前が未学習のとき（ダブルスだけのバッチの初回等）は旧方式へフォールバックし、
    **差が0.10未満なら自分/味方キャラを要確認**にする（従来は無警告で入れ替わりうる状態だった）

### v0.3.16(公開済み 2026-09-02) ゲーム画面の位置指定(配信レイアウト対応)＋バナーのリボン判定の修正
配信録画はゲームが画面いっぱいとは限らない(枠・カメラ・チャットが同居する)というユーザー要望。

- 設計: 「フレーム内のゲーム画面」を**割合(rx,ry,rw,rh)**で SETTINGS.gameRect に保存し、
  vision.js に `setSourceRect/getSourceRect/srcRect` を追加。**切り出しは全部そこ基準**
  (`frameToData`/`cropRegion`、index.html の `cropDataUrl`/`frameJpeg`/`regionJpeg`)。
  座標系は従来どおり1920x1080基準のままなので、認識ロジックは1行も変えていない。
  割合で持つので、同じOBSレイアウトなら1080p録画でも1440p録画でも同じ設定が使える
- UI: 「ゲーム画面の位置」パネル →「変更…」でモーダル。**ドラッグ選択／数値(px)入力／自動検出／
  16:9スナップ／切り出しプレビュー**。全ファイル共通の設定として保存
- 自動検出: 時間方向に動いている画素の範囲＝ゲーム画面(静止した枠・ロゴ・チャットは動かない)。
  **等倍で走らせるのが必須**(下記)。列/行の投影を「中央値の30%」でしきい値化して最長ランを取る
- **精度の勘所: ずれは解像度低下よりずっと効く**。合成テスト(1920x1080の中にゲーム1408x792=横73%)で
  | 指定 | コート | 自分キャラ | 相手キャラ |
  |---|---|---|---|
  | 全画面(元動画) | 0.984 | 0.999 | 0.963 |
  | 正確な矩形 | 0.988 | 0.993 | 0.957 |
  | **4pxずれた矩形** | **0.835** | **0.776** | **0.716** |
  → 縮小そのものの損失はほぼゼロ。**1px単位で合わせることが全て**なので、自動検出は等倍で行い、
  数値入力欄(OBSのソース位置をそのまま入れられる)を用意した
- 合成テスト全項目: scan=vs@10-13/winner@142-144(全画面と同一)・コート0.988・キャラ0.993/0.957・
  勝敗パネル t=144.75 row1・パネルアイコン0.993/0.930・勝者スコア7・**ラケット4件すべて0.966〜0.989で正解**
- テスト素材の作り方: CapCut同梱ffmpegで元動画を縮小し、静止背景＋チャット枠＋カメラ(動く)を合成
  (`samples/stream-layout-test.mp4`・生成コマンドは docs/game-screen-rect.md)
- 位置指定なしでこの動画を読ませるとイベント0件になるので、**VS画面が1件も無い場合は
  「ゲーム画面の位置を指定してください」と警告**するようにした

### v0.3.13(公開済み 2026-08-31・相手名の自動入力を刷新)
ユーザー報告「文字数や似た名前だと誤って補完される」の原因調査と対策。

- **原因**: 照合が名前欄(410x85)全体を32x8マスにした白塗り量の相関だった。2〜3文字の名前だと
  32列中10列ほどしか文字が無く、残りの「空白」が一致する＝**文字の形ではなく文字数と配置を見ていた**
  - ユーザー辞書(53人/64枚)の全ペア実測: **別人なのに0.90以上が20組・全て同じ文字数の短い名前**
    (ぱぱ↔りな=0.969 / ぱぱ↔かみ=0.964 / すー↔な～=0.960 / ゆあん↔だゆう=0.938)
  - 同一動画23プレートの実測: **同一人物 0.656〜0.670 / 別人 最大0.835 と逆転**。
    しきい値0.90は「同一人物には当たらず、短い名前同士でだけ誤爆する」位置にあった
  - ダブルスは左列が右寄せ・右列が左寄せ・欄サイズも違う(370x64)ため、同一人物の一致率も落ちていた
- **対策**: 照合シグネチャを **白文字のインク枠を切り出して48x12へ正規化** したものに変更(V.nameSig)
  - 明るいベタ帯(コート/UIの横線)は行ごと除外・文字帯はインク行の最も背の高い連続塊・
    列も塊化して最も幅の広い塊(プレート右端の細い光を除く)
  - **文字列の縦横比ゲート**(同一人物は実測で比1.0000・許容1.12)
  - **僅差ガード**: 異なる名前の2位と0.05差未満なら自動入力しない(キャラ/コート照合と同じ規則)
  - 引き継ぎ(propagateName)も同じシグネチャに統一 → ダブルスの左列⇔右列をまたいでも一致する
- **実測(同素材23プレート)**: 同一人物 0.984〜0.986 / 別人 最大0.325 の完全分離。
  leave-one-out(1枚を辞書から抜いて当てる)で **正解8/誤り0/取りこぼし0/正しい棄権15**
  (旧方式は同一人物が0.67で閾値に届かず正解0)
- 既存のユーザー辞書(旧形式)は**照合には使わない**(誤爆源のため)。名前候補プルダウンの履歴としては
  引き続き使う。新形式(s)は名前を手入力/修正してCSV保存するたびに貯まる
