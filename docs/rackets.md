## 実装メモ

- 検出: bannerBand(FHD y690-1010)の純白グリフ塊（幅280+・高さ32-110・高彩度リボン隣接）
- 照合: **列プロファイルの1次元相互相関**（バナーは横スライドし続けるため平行移動不変が必須。同一=0.98-1.00 / 異種=0.5-0.75 / 閾値0.85）
- 帰属: バナー前後のFVゲージ(fvL/fvR)減少量（drop≥0.15かつ差≥0.08。ブーストは減りが緩やかなので後方サンプルは+4秒まで）
- 辞書収穫: DBのラケット登録をGTに、ゲージ帰属した側のラベルで自動収穫（harvest fever set: myRacket/oppRacket）
- 未知バナー: 低スコア→要確認フラグ＋バナー画像をレビューUIに表示（ユーザーが上表から選ぶ→動画ごとに辞書が育つ）
- バナーは斜め表示の種類がある（メタルブースト実測: 文字ボックス高131px@FHD）→ collectBanners は maxH160 で探索（2026-08-27）
- 試合中の相手ネームプレート表示（黒帯の名前テキスト）が findBanner を通過して低スコアイベントになる → score<0.7 はフラグ根拠にしない（詳細 docs/racket-gt-check-fhd-2026-08-27.md）
- カタログ動画(00-49-49)は各ラケットのショット演出は映るが**バナー文字は出ない**ため辞書化には未使用（キャプション文字は別フォント）
- **オフライン対戦(COM/ローカル)は発動演出がカットインになり、ショット名が「黒帯に白文字のキャプション」で
  横スライドする＝色リボンが無い**（2026-08-31 パイロット 23-55-06.mp4 で実測: ribbon=0.000 / darkIn=0.433 /
  幅1034px / 高さ90px / x0=804〜920・x1=1838〜1919）。findBannerのリボンゲート(>=0.15)だけで落ちるため
  **オフライン録画では発動が1件も検出されない**。文字の寸法と既存19種への照合スコア(最大0.885＝未収穫の典型値)は
  ランクマのバナーと同じ土俵に見えるので、**収穫プローブ側でリボン条件を外せば収穫できる見込み**
  （アプリ本体のゲートは触らない＝ランクマ側の誤検出リスクを増やさない）。
  検証待ちのプロファイルは `samples/frames/pending-caption-profiles.json`（ドッスンラケット・4本）。
  **収穫済みラケットでの対照録画で0.93以上に乗ることを確認してから**辞書へ入れること
- オフライン録画では回線アイコンが出ない → HUD可視ゲートが通らず**FVゲージのside帰属は不可**
  （辞書収穫は目視ラベルなので支障なし）
