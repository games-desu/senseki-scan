## 設計を縛る事実（実測で確定・ここを外すと必ず壊れる）

### カメラ

- **ラリー中もカメラは動く。** 固定ではない。2.3秒でファーベースラインのyが118→181px、
  同一ラリー内でキャラの見かけの高さが 140px→360px（2.5倍）まで変わる。
- **ただし回転はしない**（ヨー・ロール・画角すべて固定）。動くのは位置だけ＝ドリー。
  → 消失点が **(960, −651)** に固定され、ホモグラフィは8自由度でなく**3自由度**に縮退する。
  `K = cosθ/f = 2.796e-4` は**全コート・全解像度で共通**。フレーム毎に解くのは c0, c1, Xc の3つだけ。
- 「1コート1回の校正」は**不可**。フレーム毎推定が必要。
- ラリー中のドリーは最大 **5px/frame**。参照フレーム差分方式の検出器はこれで破綻する。

### 得点HUD

- ピップ中心 x = 左 46.5+25k / 右 1722.5+25k（k=0..6・ピッチ25px）、中心 y=1011。
  **別コート・別fps・別録画機材で完全一致。**
- ポイント境界は「点灯ピップ数の増加」では取れない。**HUDの消灯区間（約2.4〜2.6秒）**で取る。
  デュースでピップが7個→2個に減るため、数えると必ず壊れる。
- HUD復帰はフェードインで、**数字が出る前にピップだけ立つ**フレームがある。
  数字幅が読める状態（numW>=30）まで待たないと偽ポイントが出る。

### ボール検出

- 色条件（960空間）: `g >= 160 && r/g ∈ (0.84, 1.02) && b/g ∈ (0.28, 0.68)`
- **g の下限160が要**。ネットのメッシュは g=125〜141 で r/g=0.96〜0.98 とボールの帯に入る。
  ボール核は g=215〜221。g=140 だと追跡がネットに乗り移る。
- **どの色のトレイルも r/g がこの帯の外**（青0.67 / 紫2.34 / 赤1.58 / 黄1.06 / 白1.00）。
  ボールだけが帯に入るので、トレイルと融合したCCからも本体を取り出せる。
- 偽陽性の常連: **ハナチャンの頭の白い花**（960縮小で花芯がボール色になり、キャラと一緒に滑らかに動く）。
- 処理は **960x540**。480x270 はボールが3.5pxになるので不可。

### 追跡

- **貪欲な単一仮説トラッカは使ってはいけない。** 一度食いついた対象を離せず必ず破綻する。
  全候補を集めてから動的計画法で鎖を作り、後から本物を選ぶ。
- 鎖の選別は**長さではなく「縦の運動量(vertRatio)と塊の大きさ(nAvg)」**。
  長さで選ぶと花（28コマ）が本物のボール（13コマ）に勝つ。
- **フラッシュ判定を絶対閾値にしてはいけない。** 砂コートは L>225 の画素が常時3.5%あり、
  「brightRatio > 0.03」だと全フレームがフラッシュ扱いで追跡が一度も走らない。

### 打点／バウンドの判別

**エフェクトは使わない。** 原理はテニスの物理そのもの:

> 打点では奥行きZの進行が反転し、バウンドでは反転しない。

地面平面ホモグラフィの見かけZは高さ h の分だけずれる:
`Z_app = Z_true + h·B(Z)`, `B(Z) = (c0 + c1·Z)/K`（実測と0.05m以内で一致）。
側 `s`(+1=奥 / −1=手前) で符号を揃えてバイアスを引く:

```
qc = -s·dZ + s·B(Z)·0.07        dZ = イベント後0.03〜0.50秒の見かけZの最小二乗傾き
判定: qc > 0.15 → 打点 / それ以下 → バウンド
```

人手ラベル12件で**判定できた11件が11件正解**。打点 0.252〜1.078 / バウンド −0.222〜+0.008。
**とびつき（エフェクト無し）でも qc=0.349 で正しく打点判定**される。

イベント候補は画面yの極大では足りない（弱いバウンドととびつきは反転しない）。
**見かけZ速度の折れ（kink）**を主候補にする。

## ショット種別（Phase D・未実装だが仕様は確定）

コート面の彩度・輝度の90%tileを毎フレーム測り、3分岐でエフェクト画素を取る:

```
whiteCap = (lineL < L90+60) ? 255 : lineL-10
isEffect = (S > S90+0.08 && V > V90-0.05)                       // 彩度分岐
        || (L > L90+25 && S > 0.30 && hueDist(H,Hmed) > 12)      // 輝度分岐
        || (S < 0.22 && L > L90+25 && L < whiteCap)              // 白分岐
```

CC → PCA長軸 → **先端で色相を採る**（尾に向かって色相が流れるため。最先端15pxはボール本体なので捨てる）。
色相の目安: topspin 先端28-42 / lob 54-55 / slice 197-207 / flat 287-314 / drop は彩度<0.20。

TP は 69.5〜93.5%、FP は 0.1〜5.4%（6コートで実測）。

**色相が被る組み合わせのフォールバックが必須**:
クレイ赤×赤（尾がコート色と同一→先端で判定）/ 砂×黄（H/S/V全一致→3フレーム差分必須）/
青ハード×青（ΔS=+0.05しかない→輝度分岐が主役）/ トップスピンとロブ（Htail が15°差→弾道併用）。

### 確定した根本原因（すべて実測）
1. **「打点直後0.2〜0.4秒の欠測」の正体はオクルージョンではない。** 真の遮蔽は局所白フラッシュ2コマ級のみ。主犯は静止物フィルタ(overlap>=0.6)で、overlap≒1−移動量/見かけ直径のため、減速期・山頂点・カメラ軸方向・手前の大玉がすべて巻き添えになる（ボール点の21.7%・12ラベル全件）。被害の本体は点の欠落でなく**鎖の分断**
2. ネット帯の丸ごと除外(136 FHD px)が欠測の18.7%。ネットのメッシュは isBall の g>=160 で落ちるので帯は過剰防衛
3. candidates() のゲート順序バグ: 融合CC再重心づけが n>3A ゲートの後ろにあり、重症例(n/A 7〜45)で一度も走らない
