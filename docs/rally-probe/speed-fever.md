# 球速ボードとフィーバーモードUI

最終更新 2026-08-24。A項（球速ボード）＝確定。**B項（フィーバーUI）＝確定（本文 B1〜B8）**。
座標・閾値・推奨アルゴリズムは末尾にまとめてある。

## 判定

**A項: 球速ボード = サーブ速度専用。ラリー中のショットでは更新されない。**
→ ラリー解析の特徴量としては「そのポイントのサーブ速度」1個しか取れない。ショット単位の速度取得には使えない。

**B項: フィーバーモードUI = 検出容易。**
- FVゲージ（2ストック）の総量を 5Hz で追い、**片側だけが約1.00落ちた瞬間 = そのプレイヤーの発動**。
  実測 `01-08-30` で **10/10 検出・誤検出0**。
- 発動バナーの表示 = 下部コーナー得点HUDの消灯 = **1.39秒ちょうど**。ポイント境界（2.60秒）と長さで分離できる。
- **「〇〇ショット」系ラケットは約1.2秒のカットイン（キャラ大写し）があり、その間ラリー追跡は不可能**。
  **「〇〇ブースト」系にはカットインが無く、追跡を継続できる。**
- 下部の得点HUD（数字＋7ピップ）・ポイント境界のスコアバナー・カメラモデル（消失点固定）は
  **クラシックと完全に同一**。得点まわりのロジックは共通化できる。
- **既存 `vision.js` の `fvL/fvR` はROIがズレており、そのままでは帰属判定が機能しない**（B1・要修正）。

# B項: フィーバーモードUI（実測確定 2026-08-24）

実測（720p → FHD = ×1.5）。左右は `x_right = 1279 - x_left`（720p）で完全ミラー。

**重要: ストック1とストック2は描画幅が違う**（内側62px / 外側94px、720p実測）。
にもかかわらず **ゲーム内単位では等価**。実測で確認:

`FV総量 = fill1 + fill2`（0.0〜2.0）になる。

### 既存 vision.js の fvL/fvR はズレている（要修正）

```js
// 現状
fvL: { x: 305,  y: 72, w: 160, h: 20 },   // FHD → 720p x203..310, y48..61
fvR: { x: 1540, y: 72, w: 160, h: 20 },
```
- **x方向: 実測のストック2（FHD x321..461）だけを見ており、ストック1（FHD x216..308）が完全に範囲外。**
  → FVが1ストック以下で発動した場合、`gaugeFill` は 0 のままで変化せず、**帰属判定が必ず失敗する**。
- **y方向: FHD 72..92 のうち上半分（72..80）はゲージ外の黒枠**。実ゲージは FHD y81..96。
  最大でも fill 0.4 程度にしかならず、`drop>=0.15` という閾値と噛み合っていない。

**修正案（FHD）**
```js
fvL1: { x:216,  y:81, w:93,  h:16 },  fvL2: { x:321,  y:81, w:141, h:16 },
fvR1: { x:1611, y:81, w:93,  h:16 },  fvR2: { x:1458, y:81, w:141, h:16 },
hpL:  { x:216,  y:56, w:151, h:13 },  hpR:  { x:1554, y:56, w:148, h:13 },
```
`gaugeFill` の述語（`lum>90`）はそのままで良い（実測で背景の抜けは無し）。
**FV総量 = gaugeFill(fvX1) + gaugeFill(fvX2)**。

## B2. HPバー = フィーバーモード固有のルール要素（KO表示あり）

- **HPは試合単位で単調減少する**（`01-08-30` 第1試合で右プレイヤー: 0.86 → 0.82 → 0.80 → 0.76 →
  0.58 → 0.51 → 0.49 → 0.32 → 0.27 → 0.24 → 0.16 → 0.09 → 0.01 → 0.00）。ポイントごとのリセットは無い。
- **フィーバーショットを食らった直後に大きく落ちる**（例: 左が t≈147.8 に発動 → 右HP 0.76→0.58）。
  それ以外にも小刻みに減る（難しい返球のたびに減っている様子）。
- **HP=0 でも即敗北にはならない**。実測: 右HPは t≈266 に 0 になったが、試合は t≈271 まで続き、
  最終スコアは **7-2**（Winnerパネルで確認）。得点は最後まで7点先取ルールのまま。
- **HP=0 の表示**: `t=268.4` の実フレームで、右の **顔アイコンの絵と `HP` ラベルがグレースケール化**し、
  HPバーは枠だけになる。→ HP切れ状態は「顔アイコンの彩度が落ちる」ことで検出できる。
- コート上のキャラの頭上にも小さな `HP` バーが浮くことがある（`a_105`: 両者、`b_260`: 右のみ）。
  **常時出ているわけではない**（被弾後しばらくだけらしい）。プレイヤー位置のアンカーには使えない。
- HPバーの塗りは**シャイン（光沢）アニメが走る**ため、面積率が ±0.09 程度揺れる。
  値を読むなら 0.5秒窓の最大値を取るか、「点灯している最右列」で測ること。

3. **バナーの表示時間 ＝ コーナー得点HUDの消灯時間 ＝ 1.39秒（83〜84フレーム）**、ショット/ブースト共通。

`01-08-30` 100〜275秒（5fps・875サンプル）で、下部コーナー得点HUDの消灯区間を全数列挙:

| 消灯区間 | 長さ | 正体 |
|---|---|---|
| 100.6-103.2 / 149.6-152.2 / 165.0-167.6 / 174.4-177.0 / 201.4-204.0 / 225.8-228.4 / 236.0-238.6 | **2.60s** | ポイント境界（deuce-pips.md の 2.58秒と一致） |

- **1.40秒 = バナー、2.60秒 = ポイント境界**で綺麗に分かれる。
- **2.80秒は両方あり得る**（バナー2連 or 長めのポイント境界）。長さだけでは決まらない。
  **FVゲージの減少があるか**で判定すること。
- ポイント境界中は**上部フィーバーHUDも完全に消える**（実フレーム `t=126.5`, `t=175.5` で確認。
  画面下中央にクラシックと同じ黒スコアバナー `ガメス [icon] 2 - 0 [icon] ケイ` ＋ピップバーが出る）。
  → **ポイント境界の検出・得点の読み方はクラシックと完全に同じロジックが使える。**
- 逆に **バナー中も上部HUDは出たまま**なので、「上部HUDが出ているか」がポイント境界とバナーを
  切り分ける第2の指標になる（下記 `hudTop`）。

### 上部HUD在否ゲート（実測値）

| 指標（720p ROI） | ラリー中 | バナー中 | ポイント境界中 |
|---|---|---|---|
| `icoLblue` = 左顔アイコン枠 x18-112,y40-66 の `isBlue` 率 | **0.56** | **0.56** | 0.00〜0.08 |
| `icoRorng` = 右顔アイコン枠 x1167-1261,y40-66 の `isOrange` 率 | 0.30 | 0.30 | 0.04〜0.15 |
| `borderCy` = 左FVストック境界 x206-212,y54-64 のシアン率 | 0.48〜0.66 | 0.56〜0.79 | **0.00** |

**最終的に検証で決めたゲート（AND ＋ 上限つき）**
```js
hudTop = (0.25 < icoLblue && icoLblue < 0.90) && (0.35 < borderCy && borderCy < 0.95)
```
- **AND** にする理由: `icoLblue` 単独だと HUD のフェードイン中（顔アイコンが先に出てゲージが後）に
  真になり、まだ滲んでいる FV を読んで**偽の発動**を出す（`01-08-30 @152.2` で実測）。
- **上限（<0.90 / <0.95）が要る理由**: `00-57-56` の第2試合（青ハード・スタジアム）では
  **ポイント間に全画面の青いワイプ**が入り、`isBlue` も「シアンの境界線」判定も**全画素で真**になって
  両方 1.00 に張り付く。上限で弾かないと偽発動が3件出た（`@267.6 / 279.8 / 289.6`）。
  なお実測でこのワイプ前後の FV は 0.55/0.71 のまま**変化していない**（ゲージはリセットされない）。

## B5. 発動の検出と「どちらが撃ったか」— FVゲージ差分が本命

**FV総量 = fill(stock1) + fill(stock2)（0〜2）を 5Hz で追い、1サンプル(0.2s)で ≈1.00 落ちた側が撃った側。**

実装した判定式（実測でチューニング済み）:
```
hudTop が 3サンプル以上連続して真、かつ 直前サンプルとの間隔 <= 0.45s のとき
  dL = prevL - L, dR = prevR - R
  0.75 < dL < 1.25 かつ |dR| < 0.25 → 左（自分）が発動
  0.75 < dR < 1.25 かつ |dL| < 0.25 → 右（相手）が発動
```

`01-08-30` 100〜275秒での結果（誤検出1件のみ・取りこぼし0）:

|---|---|---|---|

## B8. ルールK（コート基準 S90/V90）はフラッシュ中に破綻する（実測）

| FAR | 126 / **0.54** / 0.80 | 71 / **0.85** / 0.75 |
| NEAR | 121 / **0.52** / 0.83 | 42 / **0.67** / 0.76 |

## 推奨アルゴリズム

### 0. 前提
- 走らせるのは **試合区間（vs → winner）の内側だけ**。Winner/レートパネルで HUD ゲートが誤作動する。
- モード判定: **上部フィーバーHUDの有無**（`hudTop` が試合中ずっと真ならフィーバー、常に偽ならクラシック）。
  レートパネルの `mode2`（フィーバーラケット あり/なし）と二重にチェックできる。

### 1. 1パスで撮る時系列（5Hz、コスト小）

```
for t in matchStart..matchEnd step 0.2:
    seek(t)
    L1=fill(fvL1); L2=fill(fvL2); R1=fill(fvR1); R2=fill(fvR2)
    FVL=L1+L2 ; FVR=R1+R2                     # 0..2
    HPL=fill(hpL); HPR=fill(hpR)
    hud = fill(divL)>0.25 || blueFrac(icoL)>0.25
    pipL=fill(PIP_L,isScoreBlue) ; pipR=fill(PIP_R,isScoreOrange)
```
5Hz・175秒で 875サンプル。1サンプルあたり読む画素は 6千程度なので実時間で回る。

### 2. 区間ラベリング

```
hudBottom = pipL>0.25 && pipR>0.25          # 下部コーナー得点HUD
off区間 = hudBottom が偽の連続区間
  長さ 1.2〜1.7s              → バナー1本
  長さ 2.3〜3.0s かつ hud(上部)も偽 → ポイント境界
  長さ 2.3〜3.0s かつ hud(上部)が真 → バナー2本（連結）
  それ以上                    → 試合終了/リプレイ
```
**上部HUDの在否を併用するのが肝**。2.6〜2.8秒はどちらもあり得るので長さだけでは決まらない。

### 3. フィーバー発動イベントの抽出（側つき）

```
run = 0
for each sample:                      # 試合区間の内側のみ
    run = hudTop ? run+1 : 0
    if run >= 3 and (t - prevT) <= 0.45:
        dL = prevFVL - FVL ; dR = prevFVR - FVR
        if 0.75<dL<1.25 and |dR|<0.25 : emit(t, side='me')
        if 0.75<dR<1.25 and |dL|<0.25 : emit(t, side='opp')
    if hudTop: prevT,prevFVL,prevFVR = t,FVL,FVR
```
実測: `01-08-30` 100〜275秒で **10/10 検出・誤検出0**、`00-57-56` 60〜325秒で **"??" 0件**
（試合外の3件は試合区間ゲートで落とす）。

### 4. ラケット名の同定

```
for each 発動イベント e:
    banner区間 = e.t の 1.0〜1.2秒前に始まる off区間
    tCap = banner区間の中央
    b = captureStableBanner(video, tCap, bannerBand)
    racket = argmax_over_dict profileXcorr(b.profile, dict[k].profile)   # 閾値 0.85
    帰属 = e.side                # ← バナーからではなく FV から取る（ここが既存実装との違い）
```
- **`collectBanners` の `t += 4.0` は廃止**。イベント駆動にすればペア発動を取りこぼさない。
- ハテナラケット判定（同一側から複数種のバナー）は、この `e.side` を使えば従来どおり成立する。

### 5. ラリー解析の除外区間

```
除外区間 =
   ∪ ポイント境界（HUD消灯 2.6s）                     … クラシックと同じ
 + ∪ [バナー開始, バナー開始+1.4s]  ただし ラケットが「〇〇ショット」系のときだけ
 + ∪ フラッシュフレーム（S90 が コート表から ±0.12 以上ずれるフレーム）
```
- **「〇〇ブースト」系のバナー区間はラリー追跡を続けてよい**（カメラがラリー視点のまま）。
  ただし下部コーナー得点HUDは消えているので、得点の読み出しだけは止める。
- ショット系は約1.2秒がカットインで、その間ボールもプレイヤーも追えない。
  ラリーのショット数を数える用途なら「この区間で 1ショット（フィーバーショット）」とカウントする。

### 6. HP を特徴量として使う場合

```
HP = fill(hpL/hpR) を 0.5秒窓の最大値で平滑化（シャインアニメで ±0.09 揺れるため）
KO状態 = 顔アイコン領域の彩度中央値が通常の半分以下（HP=0 でグレースケール化する）
```
HP は試合単位で単調減少し、フィーバーショット被弾で大きく落ちる（0.76→0.58 の実測例）。
**HP=0 になっても試合は終わらない**（実測: t≈266 に 0 → t≈271 まで継続 → 7-2 で決着）。

## 落とし穴

### A項（球速ボード）
- 球速ボードは3Dオブジェクトなので**固定ROI不可**。テンプレ/色でボード自体を探す必要がある。
- サンド・石畳では画面上端で見切れる。カメラの上下動で数字が完全に隠れることがある。
- 720p素材では数字が15px程度。

### B項（フィーバーUI）
1. **`vision.js` の `fvL/fvR` は現状ズレている**（ストック2しか見ておらず、y も半分がゲージ外）。
   1ストック以下での発動は `gaugeFill` が 0 のままで**絶対に検出できない**。B1 の座標に置き換えること。
2. **FVゲージのストック1とストック2は描画幅が違う（62px / 94px @720p）が、ゲーム内単位では等価**。
   px幅で合計してはいけない。各箱を自分の幅で正規化してから足すこと。
3. **1ストック以上たまるとゲージが虹色にアニメする**。色相ベースの判定は全部壊れる。輝度だけ見る。
4. **ポイント境界では上部フィーバーHUDも消える**。ゲート無しで `gaugeFill` を読むと背景を拾い、
   実測で「1.99 → 1.00」という**偽の発動**が出た（`01-08-30 @103.0`）。
5. **発動は 1.4〜1.6秒間隔でペアになりやすい**（発動→相手のカウンター）。
   `collectBanners` の `t += 4.0` は 2本目を丸ごと飛ばす（実測で 3/10 = 30%）。
6. **バナーは左右どちらが撃っても画面右下（右端 FHD x≈1837）に出る**。位置から側は判定できない。
7. **リボンの色はラケット固有で、側の色ではない**（ドロドロ=黒、オシダシー=橙、カーブ=黄）。
   黄リボンは Winner パネル（黄ハイライト）と衝突する既知の誤検出源。
8. **フラッシュは明にも暗にも振れる**（ドロドロ=暗転で平均輝度 125→70、カーブ=青白く明転）。
   「明るくなったら演出」という片側ガードは効かない。**S90 の逸脱**で見るのが正解。
9. **ドロドロショットはコートに黒いインクを永続的に残す**（発動〜試合終了まで）。
   コート面の色プロファイルが試合の途中から変わる。中央値ベースの背景モデルは張り直しが要る。
10. **キャラ頭上の小さな `HP` バーは常時出ているわけではない**（被弾後しばらくのみ）。
    プレイヤー位置のアンカーには使えない。
11. **右ピップROIはオレンジのリボンで誤点灯する**（`オシダシーブースト` で `pipR=0.18` が残った）。
    `hudBottom` は必ず **左右のANDで判定する**（片側だけだとリボン色で騙される）。
12. Winner画面・レートパネルでも `icoLblue` が偶然 0.25 を超えることがある。
    **必ず試合区間の内側だけで走らせる。** `00-57-56` では下部HUDが 141.6〜210.0 の**68秒間**オフになる
    （Winner → レートパネル → 次試合のイントロ）。この間に偽発動が3件出た。
13. **全画面の単色ワイプがある**。`00-57-56` 第2試合（青ハード・スタジアム）のポイント間は
    **全画面が青くなる 2.4秒のワイプ**で、`isBlue` 系・色相系の割合ゲートが**すべて 1.00 に張り付く**。
    ゲートには必ず**上限**を付けること（`icoLblue < 0.90`, `borderCy < 0.95`）。
    なおこのワイプの前後で FV は 0.55/0.71 のまま変わらない＝**ポイント間でゲージはリセットされない**。
14. **HUDはフェードイン/アウトする**（顔アイコンが先に出て、FVゲージの枠が 0.4〜0.6秒遅れて出る）。
    「アイコンが見えた瞬間」に FV を読むと滲んだ値を掴む。ゲートは AND ＋ 3サンプル保持で。
