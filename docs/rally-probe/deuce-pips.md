# デュース時の得点表示（テニスボール型ピップ）— 調査中（随時更新）

対象: `samples/2026-08-20 11-02-43.mp4`（クレイ・夜/森）。1920x1080 / 60fps。座標はすべて FHD 基準。

## 判定（暫定）
**検出容易**。ピップバーは固定座標・固定サイズで、デュースは「7スロット → 2スロット」に切り替わる。
ポイントの切れ目は「点灯数の増加」ではなく **HUDの消灯→再点灯（≈2.6秒）** で取るのが確実。

## 判明した事実（確定・実フレーム確認済み）

### A. 通常時の得点表示
- 画面左下＝自分（青）／右下＝相手（オレンジ）。**大きな数字＝そのゲームの得点（0〜6）**、その下に**ピップバー**。
- ピップバーは**幅182px固定の丸ピル**。通常は**7スロット**で、得点数だけ左から黄色いテニスボール、残りは黒。
  - 例: `2026-08-20 11-02-43.mp4` 213秒 → 左「4」＝黄4＋黒3 / 右「6」＝黄6＋黒1（実測・画像確認済）
- **7点先取＝1試合**（この録画のモードでは1マッチ＝1ゲーム）。最終 8-6 で決着（下記タイムライン）。

### B. デュース（6-6）になった瞬間
- **両者の数字は「6」のまま**。
- **ピップバーが7スロットから2スロットに変わる**（バーの外形サイズは変わらない）。
  中央寄りに2個だけピップが並び、残りは**斜めストライプの塗り**になる。
  → ピル色（青/橙）の占有率が **通常0.43〜0.49 → デュース0.68〜0.77** に跳ね上がる。これが最も安定した判定量。
- デュース状態では両者とも 2ピップ**とも黒**。

### C. アドバンテージ
- アド側の**数字が「Adv.」に置き換わる**（数字とは別グリフ。幅が全く違う: 数字 幅≒55〜76px に対し **「Adv.」は幅≒194〜225px**）。
- アド側の2スロットバーは**左のピップだけ黄色**、右は黒。
- **アドでない側は「6」＋2スロットとも黒**のまま（併記ではない・8個目は増えない・リセットもされない）。
- デュースに戻ると再び両者「6」＋2ピップとも黒。

### D. ポイント間は HUD が完全に消える（最重要）
左右コーナーの数字＋ピップバーは、ポイントが終わると**消灯**し、画面下中央に
**黒いスコアバナー**（`名前 [アイコン] 数字 - 数字 [アイコン] 名前` ＋ その下に左右のピップバー）が出る。
バナー上で**得点が加算される演出**が走り、バナーが消えてからコーナーHUDが**新しい得点で復帰**する。

### 数字 / 「Adv.」
- コーナー数字: y 872–966（白フチ込みで 862–975）。左は x中心≒120、右は x中心≒1798。
- **「Adv.」は横幅が桁違い**（左: x 22–218 / 幅≒196、右も同幅）。y 875–960。
  → OCR不要。**ピル色画素の水平方向の広がり幅 > 150px なら "Adv."**、10〜90px なら数字。

### 色述語（既存 vision.js の UI 用述語とは別に定義すること）
```js
const lum=(r,g,b)=>0.299*r+0.587*g+0.114*b;
const isPipYellow=(r,g,b)=> r>190 && g>180 && b<130;   // 黄テニスボール
const isPipBlack =(r,g,b)=> lum(r,g,b)<55;             // 未点灯ピップ
const isScoreBlue  =(r,g,b)=> b>140 && b>r+60 && g<200; // 自分側ピル/数字
const isScoreOrange=(r,g,b)=> r>180 && r>b+90 && g<160; // 相手側ピル/数字
```

### バー在否・デュース判定
```js
// ピル矩形 (x0+4 .. x0+177, y0+2 .. y1-2) における自陣色の占有率 fill
//   fill < 0.25  → HUD非表示（ポイント間 / 演出中）
//   0.35 < fill < 0.60 → 通常（7スロット）
//   fill > 0.62        → デュース（2スロット）
```

## 推奨アルゴリズム（ポイント切れ目の検出）

**「点灯ピップ数の増加」で数えてはいけない**（デュースで数が減る・Adv.で数字が消える・演出で黄色が湧く）。
代わりに **HUDの消灯区間** をポイント境界とする。

```
1) 1フレームごと（実用は 5〜10fps）に左コーナーピルの fillL と右の fillR を計算
2) hudOn = (fillL > 0.25) && (fillR > 0.25)
3) hudOn の false 区間で、長さが 1.5〜4.0 秒のものを「ポイント境界」とする
   （4秒超はゲーム間バナー/リプレイ/マッチ終了なので別扱い）
4) 各境界の直後（復帰 +0.3 秒）で得点を読む:
     mode = fill > 0.62 ? 'deuce' : 'normal'
     normal: lit = 点灯(Y)しているスロット数 (0..6)  → そのまま得点
     deuce : advL = (2スロット目の左が Y), advR = 同（右バー）
             両方 K → デュース / 片方 Y → その側が Adv.
5) 得点した側 = 「前回の状態」との差分で決める:
     normal→normal : lit が増えた側
     normal→deuce  : 5だった側が6になった（= lit が増えた側）
     deuce →adv    : Y が点いた側
     adv   →deuce  : Adv. でなかった側
     adv   →試合終了: Adv. 側の勝ち
6) ラリー本体 = 「前の境界の復帰時刻 + 約1.0秒（サーブ構え）」〜「次の境界の消灯時刻」
7) 決め球（最後のショット）を探すなら **消灯時刻から 0.5〜2.5 秒巻き戻す**
   （実測: 295.8 に決め球 → 297.20 消灯 = 1.4秒前。球の飛行時間ぶん変動する）
```

## 落とし穴

- **金色コイン演出**（マッチポイント時に画面を横切る）が黄色を大量に出す → HUDが off の間は一切読まない。
- ピップ黄色判定を `vision.js` の `isYellow`（r>200,g>170,b<95）そのままにすると砂コートを拾う恐れ。
  ピップは**バー内の小窓のみ**を見るので実害は小さいが、専用述語を使うこと。
- 通常バーの「0点」も 2スロットの「デュース0点」も「黄0個」なので**点灯数だけでは区別できない**。
  必ず fill（ピル占有率）または「x0+16 の位置にピップがあるか」で 7/2 スロットを先に判定する。
- 「Adv.」は数字OCRに掛けてはいけない（幅で先に弾く）。
- バナーのピップバーは**コーナーより y が 16px 上**（y 977–1014）。同じ y を使い回すと読めない。
