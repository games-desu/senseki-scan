# ボール追跡とバウンド判定（ストローク/ボレー） — v3（完成）

## 判定

**検出可能だが要工夫。**

- **ボール検出（色）は9コート中の実測7コートすべてで成立**。r/g・b/g 判定はコート面・キャラ（サンボ含む）を確実にはじく。
- **ボレー（バウンド前打球）の実例を60fps連番で確定**（`00-57-56` 青ハード t=328.40〜328.98）。
  打点でのボール↔影の距離 **dy=132px(720p)=198px(FHD)**、バウンド時の **dy=18px(FHD)** に対し **約10倍**。
  → **ストローク/ボレーの判別は映像から可能**。
- ただし **影に依存する設計は不可**（曇天芝 `23-19-09` は影が一切出ない）。
  影なしでも成立する主判定として **「相手の打点から自分の打点までの区間にバウンド（y反転）が無ければボレー」**
  を採用し、dy は裏取りに使う。
- **ハーフボレー（バウンド直後の低い打球）とストロークの分離は不可**（実測 dy 33px vs バウンド 18px で差が小さい）。

→ ノーバウンド打球（ドライブボレー）と考えられるが、
   **接触フレームでボールがかなり低い（影との距離 ≈40px@720p = 60px@FHD ≈ 2.7×ボール直径）**ため
   ハーフボレーの可能性を完全には排除できない。**dy 単独では白黒つかない例**として記録する。

**対照例（ストローク側）**: 砂 `10-44-35` t=387.10〜387.60（拡大タイル `bz_tile.png` 30コマ）。

この打点での dy は約 33px@FHD しかなく（バウンド 18px との差が小さい）、
**ハーフボレーとストロークの区別は dy では不可能**。バウンドイベントの有無で判断するしかない。

計測環境 = 本PC / CapCut同梱 ffmpeg / Node v24。

| 対象 | 条件 | 実測 | 換算 |
|---|---|---|---|

| FHD 60秒 | デコードのみ | 2.31 s | 1,558 fps |

- **デコードは律速ではない**（全フレームでも30秒）。WebCodecs なら GPU デコードでさらに速い。

- **Web Worker 4本で 2.5〜3分**が現実的な目標。
- 生RGBのパイプ量は 960x540 で 1.56MB/frame × 42,444 = 66GB。**ディスクに落とさずストリーム処理必須**
  （本調査の Node スクリプトはストリーム処理で実装した）。

### F. 重大な落とし穴（実測）
7. **ショットのオーラでボール色が汚染される**。
   `00-39-45` t=200.5 のスライス（青ビーム）では、ボール周囲が青(88,161,222)に染まり、
   ボール本体も (140,167,80)（**r/g=0.838** — 閾値 0.84 をわずかに下回る）まで転び**未検出**。
   打球直後〜オーラ消失までは固定閾値の色検出は当てにできない → 対処はアルゴリズム 7 節。
8. **ネットのメッシュが黄緑**（サンド/芝コート）。素朴な「緑っぽい」判定だと大量誤検出。
   r/g・b/g 方式ならほぼ落とせる。
9. **白いフワフワの物体**が芝・ウッド・**石畳**のコート面に静止して存在する
   （`23-19-09` t=300 に2個、`00-39-45` t=200.5 に2個、`01-57-16` t=244.6〜245.5 に1〜3個）。
   ボールではない（30フレーム連続で動かない）。**無彩色なので b/g≈1 となり `isBall` は通らない**が、
   白ベース／輝度ベースの検出を足すときは要注意。
10. 8x8 px・fill≈0.9 の小さな偽ブロブが砂コートに毎フレーム十数個出る（h264マクロブロック起因と推定）。
    面積フィルタ（FHDで n≥100）で除去可。
11. **カメラはポイント中もドリーで動く**（camera-homography F1/F6: 見かけスケールが 2倍近く変わる）。
    数秒窓の中央値背景は破綻する。**隣接フレーム差分**か**毎フレームのホモグラフィ補償**が必要。
12. **サンプル動画の解像度が3種類混在**: 1920x1080 / 2560x1440 / 1280x720（全て60fps・6Mbps）。
    しきい値は必ず K=width/1920 でスケールすること。
13. **★v3新規: 画面端の背景を誤検出する**。`10-44-35` では x≈1914 に縦長（5〜10 x 34〜56px）の
    黄緑ブロブが毎フレーム出て、ラリー409フレーム中 **27フレーム（6.6%）で最大ブロブを奪った**。
    **ROI を x ∈ [40,1880]（FHD）に制限**すれば消える。
14. **★v3新規: 「明るい物体のそばの正常なコート面」が偽の影として検出される**。
    行内移動平均（`lum < m*0.86`）方式だと、ボールの発光トレイルが局所平均を押し上げるため
    **ボールのすぐ下 7px に幽霊影が張り付く**（`00-57-56` t=328.40〜328.72 で dy=5〜10px が連続）。
    バウンド時の真の dy 最小（18px@FHD ＝ 12px@720p）と紛らわしく、**ボレーをバウンドと誤判定する**。
    → 対策: 局所背景を **上限クリップ付き（min(L, 1.25·CL)）の局所最大**で取る、
      かつ **影候補の彩度がコート面と近い（chromaDist ≤ 0.08）** ことを要求する。
15. **★v3新規: トレイル自身が `isBall` を通り、ボールと融合して巨大ブロブになる**。
    石畳 `01-57-16` t=249 では黄トレイルごと 20x16〜26x51 / n=200〜800 の連結成分になった
    （真のボールは 720p で 9x9・n≈43）。**先端抽出（アルゴリズム 2-c）が必須**。
16. **★v3新規: キャラの「チャージオーラ」が黄緑を含み `isBall` を通る**。
    クレイ赤 `22-02-04` t=121.6〜121.9 でゲッソーの虹色オーラが n=50〜120 の
    「ボール」として毎フレーム検出された（拡大確認済み・`clay_tile.png`）。
    → **キャラ bbox の内側は減点する**か、**軌道の連続性ゲート**で落とす。
17. **★v3確認済み（安全側）: サンボ（Pokey）は黄色いが `isBall` を通らない**。
    実測 頭 (215,178,66) r/g=1.211 / 胴 (202,155,39) r/g=1.307 → いずれも上限 1.02 を超える。
    「黄色い球が縦に積まれたキャラ」でも誤検出しない。

## 座標・閾値（1920x1080基準・K=width/1920でスケール）

```js
// ---- ボール色（コート非依存・7コートで実測検証済み）----
function isBall(r,g,b){
  if (g < 140) return false;
  const rg = r/g, bg = b/g;
  return rg > 0.84 && rg < 1.02 && bg > 0.28 && bg < 0.68;
}
// 予測位置の近傍(±60K px)だけ緩める版（オーラ汚染対策）
function isBallLoose(r,g,b){
  if (g < 120) return false;
  const rg = r/g, bg = b/g;
  return rg > 0.80 && rg < 1.06 && bg > 0.25 && bg < 0.75;
}

// ---- 連結成分フィルタ ----
// 期待直径 d = 0.0155 * (y + 651)   [FHD px]   → 相手BLで13、手前で22〜26
// 期待面積 A = 0.785 * d*d          → 136 〜 530
// 採用条件: 0.35*A <= n <= 3.0*A, fill > 0.42, max(bw,bh) <= 3.0*d
// 探索ROI: x=40..1880, y=0..940（左右下スコアUI / 左上吹き出し / 上部球速看板を除外）

// ---- 影（v3改訂: 局所最大クリップ方式）----
// CL = フレーム自身のコート面輝度中央値（x∈[0.15W,0.85W], y∈[0.35H,0.92H]）
// (CR,CG) = 同帯の正規化クロマ中央値
// Lc  = min(L, 1.25*CL)                       ← 発光体で局所背景が跳ねるのを防ぐ
// B   = max( 水平±34K の Lc 最大, 垂直±34K の Lc 最大 )
// 影画素: L < 0.82*B  かつ  L > 0.28*CL  かつ  chromaDist((r,g,b),(CR,CG)) <= 0.08
// CCフィルタ: 面積 0.5*A .. 2.5*A, bw > bh*1.15, fill > 0.45, bw < 100K
// ボールとのマッチ: 0 < dy < 700K かつ |shadow.cx - ball.cx| <= 0.8*dy + 20K の中で dy 最小
//   （光源方向がコート依存: 石畳は dx/dy=+0.70、砂は左下、船/青ハードはほぼ真下）
// ※ 影コントラストが弱いコート（実測比 > 0.9）では影パイプラインごと無効化する

// ---- 判別しきい値（実測値ベース）----
// バウンド:  dy_min <= 1.4 * d     （実測 18px vs d=22px → 0.8）
// ボレー:    dy_hit >= 4.0 * d     （実測 198px vs d=22px → 9.0）
// 中間(1.4d < dy < 4d) は「ハーフボレー/低い打点」として保留 → バウンド有無で決める
```

## 推奨アルゴリズム

### 全体方針
**影は補助。主判定は「軌道の反転イベント列」**。理由:
`23-19-09`（曇天の芝）は影が一切出ず、クレイ赤ではボール影の確証が取れていない。
一方で **ボール本体の色検出は7コートで100%成立** し、**y反転の検出は影なしでできる**。

### Step 0 — 前処理
1. WebCodecs `VideoDecoder` で全フレームをデコード。**960x540 の RGBA** にダウンスケール（K=0.5）。
   - 実測: デコードは 42,444フレームで 28秒（律速でない）。
   - 解析は Web Worker 4本に分割（1本 70fps → 4本で 280fps → 11分動画を 2.5〜3分）。
   - **480x270 は不可**（ボールが 3.5px になる）。
2. シーン判定（player-position Step 0）でラリー画のみ通す。ポイント間・リプレイ・カットイン除外。
3. フレームごとに `CL, CR, CG`（コート面輝度中央値・クロマ中央値）を算出。
4. 白線マスク → 毎フレームのホモグラフィ（camera-homography: `xVP=960, yVP=-651, K=2.796e-4`、
   横線2本＋縦線1本で3自由度を解く）。ネット上端テープは使わない。

### Step 1 — ボール候補の抽出（毎フレーム）
a. `isBall` マスク → 8近傍CC。ROI `x∈[40,1880], y∈[0,940]`（FHD換算、Kスケール）。
b. 各CCについて、その重心 y から期待直径 `d = 0.0155*(y+651)` と期待面積 `A` を出し、
   `0.35A ≤ n ≤ 3.0A`, `fill > 0.42`, `max(bw,bh) ≤ 3.0d` で篩う。
c. **先端抽出（トレイル融合対策）**: `max(bw,bh) > 2.2*min(bw,bh)` または `n > 1.8A` のCCは
   トレイルと融合しているとみなし、
   - 直前フレームの速度ベクトル **v** が既知なら、CC画素を **v** に射影して **95パーセンタイル点**を先端とする。
   - **v** が未知なら、CC内で `|r/g - 0.95|` が最小の画素塊（＝最もボール色に近い部分）の重心を採る。
     （実測: トレイルは 青 r/g=0.67 / 紫 2.34 / 赤 1.58 / 黄 1.06 / 白 1.00±0.03 で、
      **どの色のトレイルも r/g が 0.84〜1.02 の外にある**。ボールだけがこの帯に入る）
d. **フラッシュ検出**: フレーム平均Lが直前より25%以上跳ねる、または `L>225` 画素率が3%を超えたら
   そのフレームを `flash` とマークし、ボール候補を採用しない（shot-color D: 白フラッシュは7〜10フレーム）。

### Step 2 — トラッキング
a. 直前の位置と速度から予測位置 `p̂` を作り、ゲート **60K px + 12K px × 欠測フレーム数** 内の
   候補を最近傍で採用（実測の飛行中移動量は 10〜32 px/frame @FHD）。
b. ゲート内に `isBall` 候補が無ければ、**`p̂` の周囲 60K px だけ `isBallLoose` で再探索**（オーラ汚染対策）。
c. それでも無ければ欠測。**連続6フレーム（100ms）まで**は3次スプラインで補間して軌道を繋ぐ
   （実測: ラリー中の最長欠測は4フレーム）。7フレーム以上空いたらトラックを打ち切る。
d. キャラ bbox の内側で見つかった候補は **スコアを半減**（チャージオーラ誤検出の抑制、落とし穴16）。

### Step 3 — 影の検出とマッチング（コート適性がある場合のみ）
a. **コート適性の自動判定**: そのコートの最初の数百フレームで、検出済みキャラの足元直下に
   `L/CL` の谷ができるかを測る。谷の比が **0.90 未満**なら影あり、**0.90 以上なら影パイプラインを無効化**
   （`23-19-09` はここで無効化される）。
b. 影マスク = 上記「局所最大クリップ方式」。**行内移動平均は使わない**（落とし穴14）。
c. ボールの下方 `y∈(by, by+700K]`、横は `|dx| ≤ 0.8·dy + 20K` の扇形で、
   面積 `0.5A..2.5A` かつ `bw>1.15bh` の最も dy が小さいCCを採用 → `dy`。
   **光源方向はコートごとに固定**（石畳=右下 dx/dy=+0.70、砂=左下、船/青ハード=ほぼ真下）なので、
   最初の数十イベントで `dx/dy` の中央値を学習して扇形を片側に絞ると誤対応が減る。

### Step 4 — イベント（打点／バウンド）の検出
a. ボールの screen-y 系列を5フレーム中央値で平滑化し、**極大点（下向き→上向きの反転）**を列挙。
   併せて速度の折れ `|Δv| > 8 px/frame（FHD）` も候補にする。
b. 各反転点を分類:
   - **打点(hit)**: 反転位置が **キャラ bbox から 0.9×キャラ高さ以内**、
     または ±5フレーム以内に **白い振り抜き弧／インパクトリング／新しいトレイルの尾端** が現れる
     （player-position F8-1,2 / shot-color B）。
   - **バウンド(bounce)**: キャラから離れており、かつ
     （影が使えるなら `dy` がその区間の**局所最小**で `dy ≤ 1.4d`）
     または（コート平面上に白リング→ショット色の星形バーストが出る: player-position F8-3）。
c. **打点フレームの精密化（オーラ汚染の本命対策）**:
   打点前後は必ず検出が飛ぶ（フラッシュ7〜10フレーム）ので、**打点フレームを直接見つけない**。
   入射側の軌道と反射側の軌道をそれぞれ **screen-y の2次式**でフィットし、
   **2本の交点の時刻**を打点時刻とする。実測データ（`00-57-56` t=328.4〜329.1）では
   入射 30フレーム / 反射 12フレーム がクリーンに取れており、**±1フレーム精度**で決まる。

### Step 5 — ★ストローク／ボレーの判別
打点 `H`（打った側 = S、時刻 `t_H`）ごとに、**直前の相手の打点 `H_prev` から `t_H` までの区間**を見る。

1. **その区間に「S 側のコート内でのバウンド」が検出されていれば → ストローク**。
   S 側かどうかはホモグラフィで Z の符号を見る（ネット中央 Z=0）。
2. **バウンドが1つも無ければ → ボレー**。
3. 影が使えるコートなら裏取り: `dy(t_H) ≥ 4.0d` ならボレー、`dy(t_H) ≤ 1.4d` ならストローク。
   （実測 ボレー 198px/d=22 → 9.0 ／ バウンド 18px/d=22 → 0.8。**10倍離れているので誤判定しにくい**）
4. **単調性ショートカット**（影不要・実測で単独成立）:
   `H_prev → H` の区間で screen-y が**単調増加（＝一度も反転しない）**なら **ボレー確定**。
   `00-57-56` の実例はこれだけで判定できた（30フレーム単調降下）。
5. `1.4d < dy < 4.0d` かつバウンドが打点の 10フレーム以内 → **ハーフボレー**（ストロークに含める）。
   実測でこの帯は分離できない（砂 t=387.55 の dy=33px, d=22px → 1.5）ので、
   **無理に細分せず「ストローク」に丸めるのが安全**。

### Step 6 — 出力
ラリーごとに `[時刻, 打った側, ストローク/ボレー/スマッシュ, 打点のコート座標(X,Z), ショット色種別]` の列。
バウンド列は `[時刻, コート座標(X,Z), イン/アウト]` として別に出す（ホモグラフィがあるので
バウンド位置は**コート平面上のイベント**として正確に取れる）。

### 実装順の推奨
1. ボール検出＋トラッキング（Step 1-2）だけ先に作り、ラリー中の検出率を可視化して詰める。
   **目標は「欠測 ≤ 6フレーム」**。実測ベースラインは 13.2%欠測・最長4フレーム。
2. y反転イベント検出（Step 4a）＋キャラ近接での打点分類（Step 4b 前半）。
   ここまでで**ラリーの打数・往復数**が取れる（＝ラリー長の指標が完成）。
3. Step 5-4（単調性ショートカット）でボレー判定を足す。**影は不要**。
4. 最後に影パイプライン（Step 3）を、適性のあるコート限定で裏取り用に足す。
