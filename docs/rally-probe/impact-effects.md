## 判定

**「打点」と「バウンド」は見た目で区別できる。ただし単純な明るさ閾値ひとつでは不可。**

1. **バウンドには一切エフェクトが出ない。** 砂 x2・ウッド x1 の実バウンドを 1/60 秒ずつ拡大目視した結果、
   砂埃も、白リングも、水しぶきも、星形バーストも、**何も出ない**。
   見えるのは「ボールが自分の影に接触する」ことだけ。地面のテクスチャも変化しない。
2. **打点には必ず「拡大する円環（リング）」が出る。** 11例すべてで出た。
   リングは**打点位置にほぼ固定されたまま半径だけ広がる**（ボールは離れていく）。
   持続 0.15〜0.25秒。**エフェクト無しの打点は 0/11**。
3. **ただしリングの強度は 3桁の幅がある。**
   通常ショット＝塗りつぶしの巨大リング（画面が飛ぶ）／
   **とびつき・守備的ロブ・弱い返球＝線幅 2〜3px の極細の白い環（3/11）**。
   後者は「ショットのエフェクト（色つきトレイル・破裂）」が**本当に一切無い**。ユーザー指摘どおり。
4. **「白い4条星フラッシュ」は打点マーカーではない。**
   マックスチャージ**完了**の合図で、打点との時間差は **−0.25秒 〜 +0.15秒** と実測でバラつく（5例）。
   チャージキャンセルもできるので、フラッシュから打点も球種も決まらない。
5. **参照フレーム差分は使えない。** カメラのドリーは実測で **5px/frame（FHD）** 出る。
   ウッドコートの明暗の板目 × カメラ移動で、差分ベースの検出器は**バウンドを 100% 誤検出**した。
   → **同一フレーム内で完結する検出器**（コート輝度の85パーセンタイル基準）にする必要がある。

## C. エフェクトが出ない／弱いケース（「エフェクト無しの打点」の割合）

### C-1. 実測した 11例での内訳

| 分類 | 件数 | 内容 |
|---|---|---|
| **完全に無エフェクト** | **0 / 11** | 該当なし。**どの打点にも最低限リングは出た** |
| **色つきエフェクトが無い（細い白環のみ）** | **3 / 11** | ①とびつき（10-44-35 387.550）②守備的ロブ（00-57-56 292.300）③黄ロブの低い打点（01-57-16 245.100） |
| 通常（明瞭なリング＋色つきトレイル） | 8 / 11 | |

→ 「**ショット種別のエフェクトが無い打点**」は **約 3/11 ≒ 27%**。
→ 「**打点の印（リング）すら無い打点**」は **0/11**（今回の範囲では見つからなかった）。
→ 共通点: **3件とも「ボールが地面すれすれの低い打点」**。
  つまり **地面すれすれの打点＝バウンドと最も紛らわしい状況で、まさにエフェクトが弱くなる**。これが本課題の芯。

### C-2. 弱いエフェクトになる条件（実測から）

1. **とびつき（伏臥スライディング）** — 実例 2
2. **守備的な低い返球／ロブ** — 実例 6・8
3. **遠側（画面上部）の打点は絶対サイズが小さい** — 実例 4（クレイ赤 遠側 y=120）
   リング最大半径は ≈40〜50px にしかならない。**ROI 半径を y から決めないと外れる**

|---|---|---|
| 円環 | **必ず出る**（11/11）。打点位置に固定して拡大 | **出ない**（3/3） |
| 明るい新規画素 | 打点中心から同心円状 | ボール本体とトレイルのみ |
| 位置 | ラケット高さ（地上 0.3〜1.6m 相当）・キャラの至近 | 地面（影と重なる） |
| ボール影 | ボールから離れたまま（低い打点では接近するが最小値が浅い） | dy が V字の谷（ball-bounce.md A-2） |

→ **リング＝打点の十分条件に近い**（誤検出源は B-4 のトレイル／チャージオーラ）。
→ **リング無し＝バウンド、とは断言しない方がよい**（弱い打点が 3/11 ある）。
  **「リング検出」を打点側の強い正例に使い、幾何（接地高さ・影・最寄りキャラ距離）を主判定に据える**のが安全。

### D-3. ★x 速度の反転（安価な補助判定・実測）

鎖の終端の前後で **x 速度がどう変わるか**を実測した。

| イベント | 直前 dx/frame | 直後 dx/frame | 判定 |
|---|---|---|---|
| 打点 22-18-37 302.100（低い返球） | **−1.2** | **+11.4** | **符号反転** |
| 打点 10-44-35 386.400 | −0.1 | −5.0 | 同符号だが大きさ 50倍 |
| 打点 22-02-04 118.583 | −0.3 | −27 | 同符号だが大きさ 90倍 |
| **バウンド 10-44-35 387.217** | −7.0 | −0.6 | 同符号・**減速のみ**（ドロップで転がりに移行） |
| **バウンド 00-39-45 502.383** | **+4.6** | **+4.8** | **ほぼ不変** |

→ **バウンドは x 速度がほぼ保存される**（ウッドで +4.6→+4.8）。
→ **打点は x 速度が符号反転するか、桁で変わる**。
→ ただしドロップの着弾（砂 387.217）は摩擦で x が急減速するので、
  **「x が大きく変わった＝打点」だけでは誤判定する**。リング検出と併用すること。

## E. 実装できる検出器の仕様

前提: ボール追跡の鎖の終端 `(t0, P=(px,py))`（FHD）が既知。960x540 で処理（ball.js と同じ）。

### E-0. まず参照フレーム差分は使わないこと（実測の教訓）

「t0−9フレームの画像と比べて明るくなった画素」を数える方式を実装して 4例で試した結果:

| 方式 | 砂 打点 | 砂 バウンド | **ウッド バウンド** |
|---|---|---|---|
| 単純差分（>28L） | 88% | 22% | **100%（誤検出）** |
| 参照を ±4px の局所最大に緩和 | 54% | 22% | **100%（誤検出）** |
| ＋トレイル方向±32°をマスク | 69% | 36% | **100%（誤検出）** |

原因は**カメラのドリー**。00-39-45 の 502.2〜502.8 では**画面が 5px/frame（FHD）動いており、9フレームで約 50px**。
ウッドコートは明暗の板目が交互に並ぶので、50px ずれるだけで広範囲が「明るくなった」と判定される。
（court-robustness の「0.2秒で3px以下」はラリー静止時の値で、**ラリー中は成立しない**。）

→ **同一フレーム内で完結する検出器にする。** 以下が実測で通った方式。

### E-1. リング検出器（`ring4.js` 実装済・reference-free）

```
入力: フレーム画像 I(t)、打点候補 P=(px,py)（FHD）
d      = 0.0155 * (py + 651)              // その深さでのボール直径（FHD px）
Rmax   = clamp(5.5 * d, 60, 260)          // 探索する最大半径

// 1) 局所コート基準（同一フレーム内）
base = P を中心に ±1.3*Rmax の正方格子を 6px 刻みでサンプルし、
       中心から 60px 以内は除外した集合の **輝度85パーセンタイル**
       （※中央値ではダメ。ウッドの明暗板目で誤検出する。実測で median→P85 に変えて
          ウッドのバウンド 100% → 25% に落ちた）

// 2) 円形カバレッジ
for r in 10..Rmax step 5:
    72方向に等角サンプル（楕円補正: dx = r*cosθ, dy = r*sinθ*(H/W比))
    cov(r) = (L > base + 30 である方向の割合)
bestCov = max_r cov(r),  bestR = argmax
```

**実測値（-0.15秒〜+0.40秒を 1/60 秒刻みで走らせた最大 bestCov）**

| ケース | 打点前の bestCov | **ピーク bestCov** | ピーク時刻 | ピーク半径 |
|---|---|---|---|---|
| 砂 打点（ドロップ） | ≤11% | **43%** | t0+0.150 | r=30 |
| 砂 **とびつき**打点 | 26〜36%（ラケット/キャラ） | **68%** | t0+0.017 | r=10 |
| ウッド ボレー打点 | ≤26% | **100%** | t0−0.04〜+0.10 | r=10〜30 |
| **砂 バウンド** | ≤18% | **21%** | — | r=90〜130（＝外周ノイズ） |
| **ウッド バウンド** | ≤21% | **25%** | — | r=10〜90（ばらつく） |

**判定ルール（推奨）**

```
isImpact(t0,P) =
   ∃ t ∈ [t0-0.03, t0+0.25]:
       bestCov(t) >= 0.38                                   // 主条件
   AND bestR が 3フレーム以上にわたり **単調に外へ**動く      // 円環が広がっている
   AND bestR(peak) <= 5.5*d                                  // 大きすぎるものは背景
   AND cov(r) が半径方向に **ピークを持つ**（r±30 で 15pt 以上落ちる）
                                                             // トレイル／板目は単調減衰なのでここで落ちる
```

- しきい 0.38 は 実測 打点 43/68/100% vs バウンド 21/25% の間。**余裕は狭い（43 vs 25）**。
- 余裕を広げる改良（未検証）: 無彩色画素には緩い閾値を使う
  `L > base+30 || (S < 0.20 && L > base+12)`。砂コートは base(P85)=198 に対し
  リングが L=228 しかないので 30 では際どい（一方コートラインが L=229 なので単純に下げられない）。

**実装上の注意**
- **base のサンプル窓は、リングが大きいと自分自身を含んでしまう**。
  ウッドのボレー例では base が 91 → 153 に押し上げられた（リング直径が窓に収まったため）。
  → **内側除外半径を 1.2*Rmax まで広げる**か、**コート多角形内・ライン画素を除いた集合**から取ること
  （shot-color.md J の L90 の取り方と同じ流儀）。
- **72方向すべてを見る必要はない**。トレイル方向（入射・出射の ±32°）を落としても
  打点の cov はほとんど下がらなかった（砂 打点 88%→69%）。ただし**ウッドの誤検出は消えなかった**ので、
  マスクは補助であって主対策ではない。

### E-2. 補助シグナル

**(a) マックスチャージ完了フラッシュ（打点の予告・±0.25秒）**
```
pureWhite(t) = count(L > 238 && max-min < 26)  // 960x540、4px 間引き
flash = pureWhite(t) > 2.0 * median(pureWhite over ±1s)
```
実測 2.1〜2.7倍で 5例すべて検出。**打点そのものではない**（−0.25〜+0.15秒のズレ）ので、
「この付近に強打がある」という**探索窓のヒント**にのみ使う。

**(b) 白い振り抜き弧**
打点の −0.05〜+0.05秒に出る細長い三日月。**円形性が無い**ので E-1 の円形テストでは拾えない。
「打点が近い」ことの弱いヒント止まり。単独では使わない。

**(c) トレイル尾端**
shot-color.md の方式で打点位置を取れるが、**とびつき・弱い返球ではトレイルが出ない**（3/11）。
必ず E-1 と併用すること。

### E-3. 全体の推奨（打点／バウンドの判別フロー）

```
鎖の終端イベント e(t0, P) について:

1. 幾何（主判定・ball-bounce.md の資産をそのまま使う）
   - 影とのdy が V字の谷 → バウンド寄り
   - コート平面へ投影した高さ ≒ 0 → バウンド寄り
   - 最寄りキャラ（player-position.md）まで < 1.2 * キャラ幅 → 打点寄り
2. **x 速度の変化（D-3）**
   - 符号反転 → **打点で確定**
   - |dx| がほぼ不変（±20%以内）→ **バウンド寄り**
3. リング検出（E-1）を t0-0.03 〜 t0+0.25 で回す
   - bestCov >= 0.38 かつ半径が外へ広がる → **打点で確定**（バウンド 3例では最大 25%）
   - 出なかった場合は 1.+2. の判断を採用（弱い打点を落とす可能性が 3/11 残る）
4. 白フラッシュが t0±0.25 にあれば「強打の可能性」フラグ（球種決定には使わない）
```

**時間窓のまとめ（打点 t0 基準・すべて実測）**

| 事象 | 窓 |
|---|---|
| ラケット振り抜き弧 | −0.05 〜 +0.05 |
| **インパクトリング出現** | **+0.017 〜 +0.05** |
| リング最大 | +0.13 〜 +0.20 |
| リング消滅 | +0.25 〜 +0.37 |
| ショット色トレイル | +0.02 〜 +0.50 |
| マックスチャージ白フラッシュ | **−0.25 〜 +0.15**（打点マーカー不可） |

→ **サンプリングは 4フレーム（0.067秒）間隔で足りる**（リングの寿命が最短でも 15フレーム）。
  ただし**とびつきの細環は 5フレームしか見やすい時間がない**ので、
  **打点候補の周辺だけは 1フレーム刻み**で見ること。

## 座標・数値まとめ（1920x1080 基準）

- ボール直径 `d = 0.0155 * (y + 651)`（camera-homography F5 の消失点 yVP=−651 由来）
- インパクトリング最大半径 `Rmax ≈ (3.5〜5.5) * d`
  - 実測: y=120 → r≈40 ／ y=235 → r≈65 ／ y=496 → r≈100 ／ y=800 → r≈85（とびつきは拡大が遅く +0.38秒でまだ拡大中）
- リング拡大速度: 通常打 **6〜10 px/frame** ／ とびつき型 **3〜4 px/frame**
- とびつき環の画素値: **RGB (228,228,228) / L=228 / S=0.00**、線幅 **≈19px**、直径 **≈160px**
- 砂コート面: RGB (219,203,100) L=197 S=0.54 ／ コートライン RGB (238,225,223) L=229 S=0.06
- pureWhite（960空間・4px間引き）のコート別ベースライン: 砂 320 ／ クレイ赤 640〜800 ／ ウッド 405 ／ 石畳 330 ／ 青ハード 250〜500
- **カメラのドリー速度: 最大 5 px/frame（FHD）**（00-39-45 t=502.2〜502.8 で実測）

## 未確認

1. **空振り・ネットイン（ネットコード）・フレームショット（芯を外した打球）・スマッシュ**の実例を
   特定できなかった。これらでリングが出るか／出ないかは**未確認**。
   特に**ネットに当たって落ちる球**は、鎖の終端がネット上に来るため打点・バウンドどちらでもない
   第3のイベントになるはず。要追加調査。
2. **サーブの打点**。サーブは専用カメラ（10-44-35 t≈382.3 で確認）で画角が大きく変わり、
   カメラも高速に振れる。今回のリング検出器がそのまま通るかは**未確認**。
3. **曇天の芝 `23-19-09`（影が一切出ないコート）でのバウンド**を実例で確認できなかった。
   影が無いコートでは幾何側の主判定が弱くなるため、リング検出への依存度が上がる。要確認。
4. **クレイ赤／青ハード／石畳／芝のバウンド**は実例を特定できなかった（確認できたのは砂 x2・ウッド x1）。
   「バウンドは無エフェクト」の結論は**3件・2コート**の根拠であることに注意。
   クレイ赤で「バウンドらしき鎖の終端」を1件追ったが（22-18-37 t=302.100）、
   **x速度も反転していたため打点だった**（実例11）。低い打点はバウンドと見分けがつきにくい。
5. リングが**打点位置に固定**という結論は、22-02-04（118.583 / 119.717）・01-57-16（304.363）・
   00-57-56（290.883）で明瞭に確認した。10-44-35 386.400 のケースだけは**中心が打点より約40px 左**にあり、
   完全な固定かどうかは**測り切れていない**。
6. E-1 の改良案（無彩色画素に緩い閾値）は**未検証**。
7. 「エフェクト無しの打点 0/11」は**今回見た 11例での値**。母数が小さい。
   特に C-2 の「地面すれすれの打点」は 3/11 と高頻度なので、実運用での取りこぼし率は別途測るべき。
