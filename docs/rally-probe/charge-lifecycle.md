# チャージ演出の解剖とキャンセル

調査 2026-08-25。担当: charge-lifecycle。
**すべて実フレームを目視＋画素値で確認。見ていないことは「未確認」と明記。**

計測は全て **640x360 に縮小したフレーム** で `pureWhite = (L>238 かつ max−min<26)` の
**最大連結成分（CC）** を数えた（作業スクリプト `flash2.js` / `scan.js`）。
座標は特記なければ 640x360 空間、FHD 換算は3倍（1440p/720p 素材も 640x360 に正規化してから計測）。

---

## 判定（結論）

1. **白い4条星フラッシュ＝「マックスチャージ完了」の合図。打点ではない。**
   7例すべてで、フラッシュは**打つ選手の胴体位置**に出て、**打点の 0.03〜0.32秒“前”**に始まる。
2. **チャージキャンセルの視覚的合図は存在しない。**「何も起きない」という形で表現される。
3. **フラッシュからは、そのショットがマックスチャージで打たれたかどうかは判定できない。**
   打点直後のトレイル（色・太さ・長さ）からも、打点のインパクト演出からも判定できない。
   → **「白フラッシュ＝マックスチャージショットが打たれた」は誤り。
   今回、映像だけからマックスチャージ打球を同定する手段は見つからなかった。**
   唯一の弱い手掛かりは**タイミング**で、「フラッシュがまだ光っているうちに打点が来る」型
   （実測 +0.03 / +0.05秒）はそのまま打った可能性が高い。ただしキャンセル確定の例Aが
   +0.27秒であるのに対し、離れる型には +0.18〜+0.32秒が混在するため、**閾値では切れない**。
4. **shot-color.md の D項・L1項・L2項の時間解釈は誤り**（§5 で訂正）。
   特に `01-57-16 @304.45` には**そもそも白い星フラッシュが無い**（最大CC が背景と同じ）。
5. **ただしフラッシュは「打点の予告」としては非常に強い**（§7）。
   フラッシュ検出 → 中心座標＝打つ選手の位置、そこから **0〜0.35秒以内**の軌跡断絶は
   **バウンドではなく打点**と断定してよい。これがラリー解析への実用的な使い道。

### 1-3. 形・色・位置

- 形：**4条の細い光条＋丸い白核**。リングでも円盤でもない。外接のアスペクトは **1.1〜1.2（ほぼ正方）**。
- 色：**完全な無彩色の白**。実測 FHD 画素 (875,176)=**(249,251,251)** ／ (820,150)=(246,246,243) ／
  (930,210)=(246,248,245)。周囲の砂コートは (218,200,125)・(210,196,122)。
- 位置：**選手の胴体〜ラケット**。足元でもボールでもない。**選手と一緒に動く**
  （8フレームで中心が 640空間 (292,59)→(284,72)＝FHD で 24px 左・39px 下へ）。
- **ボール検出（ball.js の isBall）には引っかからない**：白核は b/g≒1.0 で `bg<0.68` を外れる。
  砂とのアンチエイリアス境界も、r/g が 1.02 を割るころには b/g が 0.9 台なので通らない。
  実測（960空間・星の矩形内の isBall 画素数）: フラッシュ前 788 → フラッシュ中 477 と**むしろ減る**。
  → **偽ボールは作らない。害は「隠す」ことだけ。**

## 2. キャンセルの見た目 → **無い**（重要な結論）

386.283（フラッシュ消滅）〜386.417（打点直前）の 9フレームを、FHD 300x220 を 2倍に拡大して
1コマずつ確認した。

- オーラが弾ける／粒子が散る／色が抜ける／ラケットを下ろす等の**キャンセル演出は一切無い**
- 足元の白いオーラは**キャンセル後もそのまま**残り、打った後 0.88秒かけて元の水色に戻る
- つまり**オーラの持続はチャージ維持を意味しない**（`23-37-24 @139.47` の橙オーラも打点後まで残る）

→ **キャンセルは「何も起きない」という形で表現される。映像から検出する手掛かりは存在しない。**

- **必ず打点より前**。ズレは **+0.03 〜 +0.32秒**（7例の中央値 ≈ +0.19秒）。
  分布は二峰的に見える: **重なる型（B +0.03 / G +0.05）** と **離れる型（E +0.18 / D +0.19 / A +0.27 / C +0.29 / F +0.32）**。

  ＝ ball.js の `expectDiam` で言えば**期待ボール直径の 15〜18倍**。
  外接の充填率は 17〜18%（4条星なので隙間が多い）。

## 4. 「キャンセルされずに実際に打たれた」例 ＝ 候補は2つあるが確証は取れない

課題では「打たれた実例を2つ以上」と指示された。**タイミングでの候補は2件挙げられるが、
映像から確定はできない**という結論になった。

- **B（22-02-04 @118.60・青ビーム）と G（23-37-24 @154.15・桃ビーム）は星が打点に重なる2例**で、
  「溜め切ってそのまま打った」可能性が最も高い候補。どちらも星の発光中にボールが飛び出し、
  太い色つきビームが出る。**課題の「実際に打たれた実例2つ」に最も近いのはこの2件。**
  ただしこれは**タイミングからの推定であって確証ではない**。「星が出た直後に別の打ち方に
  切り替えた」場合と見た目で区別する材料が無い。
- **C（黄ロブ）・D（橙ビーム）・F（ベージュビーム）** はいずれも太く長いトレイルだが、
  A（キャンセル確定・白いドロップ）と**トレイルの太さでは差が付かない**
  （shot-color L3 の「トレイルの太さでは溜めを判別できない」を追認）。
- **打点のインパクト演出も種別色そのまま**：B=白リング→青紫、C=黄の星＋黄リング、
  D=橙の爆ぜ＋橙リング、A=白円盤→桃紫、E=白円盤。
  **マックスチャージ専用の打点演出は観測されなかった。**
- 球速ボードは **サーブ専用**（speed-fever.md A項）でラリー中は更新されないため、球速での裏取り不可。

→ **「打たれた／キャンセルされた」の真値ラベルはユーザーの証言以外に取得手段が無い。**
  ラベル付きデータが要るなら、ユーザーに申告してもらうしかない（この案自体は未検証）。

## 7. 推奨アルゴリズム（640x360 換算）

```js
// 1) 前処理: フレームを 640x360 に縮小。コート帯 y = 5%〜90%。
//    pureWhite = (0.299R+0.587G+0.114B > 238) && (max-min < 26)
// 2) 8近傍で連結成分を取り、最大CC の {n, cx, cy, w, h} を毎フレーム記録。
//
// 3) チャージ完了フラッシュの判定（4条件すべて）:
//    (a) n >= max(350, 0.40 * expectFlashArea(cy))   // 大きさ（遠近で正規化）
//    (b) 0.75 <= w/h <= 1.45                          // ほぼ正方。吹き出し(2.0+)とSMASHマーカー(2.4)を排除
//    (c) n(t) >= 10 * n(t-1)                          // 立ち上がりが1フレーム（実測 26→813 / 30→3264 / 35→2790）
//    (d) 続く 6〜10フレームで n が単調に減衰して背景値へ戻る   // 立ち上がりと減衰の非対称
//
//    expectFlashArea(cy_640) = 0.0012 * (3*cy_640 + 651)^2
//      実測との照合: cy=60→826(実測835) / cy=237→2216(実測2276) / cy=251→2358(実測2853,3264)
//                    / cy=262→2508(実測3044) / cy=274→2595(実測2097)   誤差 ±40%
//      ＝ 星の FHD 幅 ≈ 0.26 * (y_FHD + 651) ≒ 期待ボール直径の 15〜18倍
//
// 4) 得られる情報:
//    flashAt   = 立ち上がりフレームの時刻
//    flashPos  = (cx*3, cy*3)  … FHD の「打つ選手の胴体」座標（足元より上）
//    hitWindow = [flashAt, flashAt + 0.35s]  … この中に必ず打点がある（実測 +0.03〜+0.32）
//
// 5) 打点/バウンド判定への使い方:
//    軌跡の断絶点 P が  P.t ∈ hitWindow  かつ  |P.xy − flashPos| < 星の外接幅の 2倍
//    → その断絶は **打点**（バウンドではない）。どちら側の選手が打ったかもフラッシュ位置で確定。
//    ※ 逆は言えない。フラッシュが出ないショットの方が圧倒的に多い。フォールバック必須。
```

**必ず守ること**
- 判定は**総白画素数ではなく最大連結成分**で行う（§5 の理由）。
- **フラッシュ位置＝打点位置ではない**。選手はフラッシュ後 0〜0.32秒動く。
  実測 A では フラッシュ中心 FHD (879,180) に対し打点は FHD (770,230) 付近＝**110px 離れている**。
  位置は「どちらの選手が打つか」の帰属にだけ使い、着弾点座標には使わないこと。
- **フラッシュ中もボールは検出できる**（星は isBall を通さない）。ただしボールが星の内側に入る局面
  （＝打点が星に重なる例B型）では 2〜3フレーム完全に隠れる。
