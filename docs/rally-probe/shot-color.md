## 判定

**検出可能だが要工夫**（コート依存の穴あり）。

- **5色すべての実例を実測できた**（白＝ドロップは 2026-08-24 追加調査で確定。
  吹き出し「いいドロップだ！」「ナイステクニック!」で種別も裏取り済み）。
- **単一のルール（court-robustness のルールK）では足りない**。
  彩度ベースのルールK に**輝度ベースの分岐**と**白専用の分岐**を OR で足した**3分岐**が必要。
  実測 TP は 4色8ケースで 69.5〜93.5%、ショット無しフレームの誤検出は 0.1〜5.4%。
- **青ハードコート上の青いスライスが最悪ケース**で、彩度差はわずか +0.05。
  輝度（コートの L90 +25 以上）だけが頼り。ルールK 単独では TP 17%。
- **黄（ロブ）はサンドコートで背景と完全に重なる**（H/S/V すべて一致）。マスクは取れるが分類は不能。
- **トップスピンとロブの切り分けは色だけでは詰め切れない**（尾の色相が 15°しか離れていない）。
  軌道（弾道の頂点高さ）との併用が必要。
- **チャージ（溜め）の有無は白フラッシュの画素数で明確に判別できる**（溜めあり 16倍 / 溜めなし 1.7倍）。

## 判明した事実

### A. 「ビーム/光の柱」の正体＝ボールのモーショントレイル
`2026-08-20 22-02-04.mp4`（クレイ赤）118〜124秒、`2026-08-20 23-37-24.mp4`（芝）119〜120秒を60fpsで確認。
打球後にコートを走る色つきの帯は、**ボールが引く発光した尾（コメット状のトレイル）**。

**結論**
1. **白トレイルは S=0.00〜0.15 / L=190〜210**。ルールK（S > S90+0.08 = 0.60）では **1画素も拾えない**。
   court-robustness の「白は別枝」という結論が実データで裏付けられた。
2. **白トレイルは `isCourtLine`（L>175 && S<0.20）にそのまま一致する**。色だけではコートラインと**区別できない**。
3. **唯一の色的な差は輝度**: コートライン **L=229〜232 / V=0.93**、白トレイル **L=190〜210 / V=0.77〜0.84**。
   → **`L 185..222 かつ S<0.20`（＝白いがラインほど明るくない）**という帯で「ラインでない白」をある程度切り出せる。
   ただしトレイル先端は L=207、ライン日陰部は L=190 まで落ちうるので**輝度だけでは不十分**。
4. **決め手は「動くかどうか」**。カメラは 0.2秒で 3px 以下しか動かない（court-robustness F4）。
   **2〜3フレーム差分（±0.05秒）で 20px 以上動く白 blob だけがトレイル**。ラインは差分でほぼ消える。
5. **形状も違う**: 白トレイルは**幅の広いぼやけた円錐**（先端で細く尾で太い、境界が数十px にわたってグラデーション）。
   コートラインは**幅が一定でエッジが立った直線**。ソーベル勾配の急峻さで区別できる。
6. **ボール本体は黄緑（H=64 S=0.40 V=0.79）で白トレイルの中でもはっきり見える**。
   他の色トレイルではボールが埋もれるが、白トレイルではボールが最も彩度が高い点になる。
   → **白トレイルの「先端」は「S が極大の点」で探せる**（他色とは逆）。

|---|---|---|---|---|---|

| 同上 | (626,313) | 290.967 | L=161 @291.000 | 291.45〜291.55 | **0.48秒 = 29フレーム** |

**3ショット共通の結論**
- **立ち上がりは 2〜3フレーム（0.03〜0.05秒）で一気に飽和**する（L 125→202）。
- **減衰は指数的で 19〜29フレーム（0.32〜0.48秒）かけて消える**。
- **ピークの ±20% 以内にいるのは 8〜10フレーム（0.13〜0.17秒）**。

**★固定点で見ると色相が時間変化する（サンプリング設計上いちばん重要）**
石畳の橙トップスピンで、同じ画素の色相が
`H=41(304.467) → 40 → 37 → 35 → 33 → 31 → 27 → 22 → 17 → 13 → 8 → 1 → 359(304.717)` と
**0.25秒で 42°ぶん流れた**。青ハードの水色でも `H=205 → 203 → 211 → 215 → 220 → 223 → 226`（コート色へ）と流れた。
→ **「トレイルの空間的な色相勾配」と「固定点での時間的な色相変化」は同じ現象**。
  **色を採る時刻を打点からの経過時間で正規化しないと、同じショットが別の色に分類される。**

→ **サンプリング間隔の上限**:
  - 「打球があったこと」を取りこぼさないだけなら **6フレーム（0.10秒）間隔で十分**（最短でも 19フレーム残る）。
  - **色を確実に採る**なら**ピーク近傍の 8〜10フレームを掴む必要がある**ので **4フレーム（0.067秒）間隔**が安全。
  - 「打点フレームを特定」したいなら白フラッシュが 7〜10フレームなので **4フレーム間隔**で足りる。

### J. 検出ルールの改良版（3分岐）と全コート実測

ルールK に **輝度分岐**と**白分岐**を OR で足した式を、9コート＋4ショット例で実測した。

```js
// フレームごとに「コート多角形内・ライン画素を除いた」画素から測る
S90, V90, L50, L90 = 各パーセンタイル
Hmed = 彩度 0.15 超の画素の色相の円環中央値
lineL = ライン画素(L>175 && S<0.20)の輝度中央値（無ければ 255）

isEffect(H,S,V,L) =
     (S > S90 + 0.08 && V > V90 - 0.05)                       // 分岐K: 彩度
  || (L > L90 + 25 && S > 0.30 && hueDist(H, Hmed) > 12)       // 分岐B: 輝度＋色相ずれ
  || (S < 0.22 && L > L90 + 25 && L < lineL - 10)              // 分岐W: 白（ドロップ）
```

**TP（ショットのビーム/尾の ROI で該当した画素の割合）**

| ケース | 分岐K のみ | **3分岐** |
|---|---|---|
| 青ハード 水色ビーム `00-57-56 @291.02` | 17.4% | **69.5%** |

## 推奨アルゴリズム

前提: WebCodecs で 60fps デコード可（Electron 38 / Chromium 140）。
座標はすべて 1920x1080 換算、面積はすべて**画面比率**で持つ（F0: 720p/1080p/1440p 混在）。

### 手順0. サンプリング設計（H項の実測から決定）

- トレイルは**最短でも 19フレーム（0.32秒）持続**する（3ショットで実測）。
- ピーク近傍（色が安定して濃い）は **8〜10フレーム（0.13〜0.17秒）**。
- マックスチャージの白フラッシュは **8〜10フレーム**。

```
粗探索: 4フレーム間隔（0.067秒 = 15Hz）
        → どのトレイルも 19フレーム以上あるので取りこぼしゼロ、
          かつピーク区間(8〜10f)に必ず1回は当たる。
精査  : ヒットしたら前後 ±12フレームを 1フレーム刻みで見て打点フレーム t0 を確定
        （t0 = 白フラッシュのピーク、または エフェクト画素数が 0→急増した最初のフレーム）
色採取: 必ず t0 + 6フレーム（0.10秒）のフレームで採る。
        ★時刻を固定しないと同じショットが別の色になる（H項の「固定点で色相が42°流れる」）
```

### 手順1. コート基準をフレームごとに測る（**コート多角形の内側で**）

court-robustness の推奨と同じだが、**帯の位置が決定的に効く**（I項で実証: 帯にコート外が
混ざるだけで青ハードの TP が 69.5% → 2.5% に崩壊した）。

```
1. isCourtLine = (L > 175 && S < 0.20) でラインマスクを作る
2. camera-homography の方式（消失点固定・3自由度）でコート台形を毎フレーム推定
3. 台形の内側に FAR/NEAR 2帯を切る（台形の高さの 15-40% と 60-90% あたり）
4. 帯内・ライン画素を除いた画素から
     S90, V90, L50, L90 = パーセンタイル
     Hmed             = S>0.15 の画素の色相の円環中央値
     lineL            = ライン画素の輝度中央値（サンプル 50px 未満なら 255）
```

**サニティ**: `S90 < 0.25` のとき（石畳など無彩色コート）は Hmed が
**ごく少数の有彩色画素から計算されて暴走する**（実測: 石畳でビームだけを拾って Hmed=318 になった）。
→ `S90 < 0.25` なら **Hmed を使う分岐を無効化**し、輝度分岐は `hueDist` 条件を外して使う。

### 手順2. エフェクト画素マスク（3分岐 OR）

```js
const hueDist = (a,b) => { const d = Math.abs(a-b)%360; return d>180 ? 360-d : d; };

isEffect(H,S,V,L) =
     (S > S90 + 0.08 && V > V90 - 0.05)                              // 分岐K 彩度（砂・クレイで有効）
  || (L > L90 + 25 && S > 0.30 && (S90<0.25 || hueDist(H,Hmed) > 12))// 分岐B 輝度（青ハード・木で有効）
  || (S < 0.22 && L > L90 + 25 && L < whiteCap)                      // 分岐W 白（ドロップ）
```
`whiteCap` = `lineL - 10`。ただし **ウッド／船の木甲板では `lineL`(≈187) が白トレイル先端(L≈204)
より暗いので上限を外す**（`whiteCap = 255`）。判定は
`lineL < L90 + 60` なら「ラインが暗いコート」とみなして上限を外す、で自動化できる。

**実測 TP / FP（J項）**: TP = 青ハード水色 69.5% / クレイ橙 73.5% / 砂橙 81.3% / クレイ白 92.7% /
石畳紫 93.5% / 石畳赤 85.5% / 石畳白 70.2% / 船紫 77.8%。
FP = ショット無しフレームのコート帯で 0.1〜5.4%（最悪はクレイ夜森 NEAR の 5.37%）。

**分岐B の閾値は必ず L90 基準**。L50+30 にすると木甲板 FP 57%・ウッド 45%・芝起伏 26% に爆発する（実測）。

### 手順3. 連結成分 → トレイル候補

```
1. 3x3 の膨張1回＋収縮1回（アンチエイリアスで途切れる細いビームを繋ぐ）
2. 8近傍 CC
3. 除外:
   - HUD 矩形（座標・閾値 節の一覧）
   - コート台形の外側（ただし上方向は +350px まで許可。ロブは空を通る）
   - プレイヤー矩形（player-position の推定位置を中心に、見かけサイズ×1.4 で膨張）
     ★チャージ中のキャラは虹色で全分岐に引っかかる（L4 で実測 S90=0.69 V90=0.95 L90=216）
4. 形状フィルタ:
   - 面積 >= 画面の 0.03%（FHD で 620px 相当）
   - PCA の長軸/短軸比 >= 2.2（トレイルは細長い。ドロップは太いので 2.2 は下げすぎないこと）
   - 長軸長 >= 画面高の 4%
5. 静的直線の除去（コートライン対策・白分岐に必須）
   - 同一 blob が 3フレーム前（0.05秒）のマスクにも 80% 以上重なっていたら破棄。
     カメラは 0.2秒で 3px 以下しか動かない（court-robustness F4）ので
     ラインは重なり続け、トレイルは重ならない。
```

### 手順4. トレイル先端の特定

```
1. blob の PCA 長軸の両端点 P1, P2 を取る
2. 「尾」= 直前サンプル（4フレーム前）の blob と重なっている側の端点
   「先端」= 反対側（＝1サンプルで数十px 進む側）
   ※打点直後は尾がラケット位置に固定されるので、この判定はよく効く
3. 端点が判定できない単発フレームでは、V の高い側を先端とする
   （実測: 石畳赤 先端L=194/尾L=116、船紫 先端149/尾111。ただし白ドロップと青ハード水色は
     先端・尾の輝度差が 20 以下なので、この代替は当てにしない）
4. ★先端の最先端 15px（FHD換算）は「ボール本体」なので捨てる
   ボールは H=55〜65 / S=0.35〜0.99 の黄緑。捨てないとドロップが黄(ロブ)に誤分類される
   （実測: 白ドロップの先端 3x3 が H=64 S=0.40 だった＝ボール）
```

### 手順5. 色相サンプリング

```
1. 長軸に沿って 10 分割し、各区間の
     Hi = S>0.25 の画素の色相の円環中央値
     Si = 彩度の中央値
   を出す（ボール除去後）
2. Htip  = 先端側 2区間（20%）の円環中央値
   Hcore = Si が最大の区間の色相
   Htail = 尾側 2区間の円環中央値
   Smed  = 全区間の彩度中央値
3. 白判定は Smed で行う: Smed < 0.20 → 白（ドロップ）
```

| トップスピン（赤） | 28〜42 | 27〜30 | **358〜7** | 22-02-04@120.7 / 01-57-16@304.6 / 23-19-09@301.1 |
| ロブ（黄） | 54〜55 | 41〜54 | 22 | 22-02-04@122.8 / 10-44-35@405.4 |
| スライス（青） | 197〜207 | 200〜205 | 207〜228 | 22-02-04@118.7 / 00-57-56@291.0 / 23-19-09@480 |
| フラット（紫） | 305〜340 | 287〜314 | **265〜293** | 22-02-04@120 / 23-37-24@119.8 / 01-57-16@302 / 00-57-56@105.6 |
| ドロップ（白） | – | – | – | Smed 0.03〜0.15 |

### 手順6. 5色分類

```js
if (Smed < 0.20)                       return 'drop';        // 白
if (250 <= Htail && Htail < 345)       return 'flat';        // 紫
if (185 <= Htail && Htail < 250)       return 'slice';       // 青
if (Htail >= 345 || Htail < 15)        return 'topspin';     // 赤
if (15 <= Htail && Htail < 40) {                              // 赤とロブの境界
    return (Htip >= 48) ? 'lob' : 'topspin';
}
if (40 <= Htail && Htail < 70)         return 'lob';         // 黄
return 'unknown';
```

**トップスピンとロブは色だけでは詰め切れない（正直に書く）**
実測で `Htail` は トップスピン 358〜7 / ロブ 22 で **15°しか離れていない**。
さらに青ハードの橙トレイル（281.90）は Htail=21・Htip=30 で**どちらとも取れる値**だった。
→ **確定は軌道で行うこと**: ロブは弾道の頂点が画面上端付近まで上がり、トレイルが**ほぼ垂直**になる。
  ball-bounce / camera-homography 側の軌道推定と併用し、
  「頂点高さ > ネット高の3倍」なら色に関わらず lob に倒す、という後段ルールを推奨。

### 手順8. 打った側の判定

トレイルの**尾側の端点＝打点**。手前（画面下）なら自分、奥（画面上）なら相手。

### 手順9. チャージショットの判定（L2）

```
pureWhite(t) = 「L>238 かつ max−min<26」の画素数（640x360 換算・コート帯 y 6%〜85%）
base = 直近1秒の pureWhite の中央値（実測 133〜140）
if (pureWhite(t) > base*5) が 4フレーム以上連続 → チャージショット（マックス溜め）
```
実測: 溜めなし 230px（base の1.7倍）／溜めあり 2153px（16倍）。閾値 5倍で明確に分離。
**トレイルの太さ・長さでは判別できない**（L3）。

## 落とし穴

1. **インパクトリングの色は時間変化する** → 色分類に使わない（トレイルのみ）
2. **トレイルは色相勾配を持つ**（先端が黄/桃寄り、尾が濃い赤/紫寄り）。
   **同じ画素を時間で追っても同じ勾配が流れる**（石畳の橙で 0.25秒に 42°）。
   → 採取は**先端側**、かつ**打点からの経過時間を固定**（t0+6フレーム）して行う。
3. **トレイルの最先端はボール本体（H=55〜65 の黄緑）**。捨てないとドロップやスライスが黄(ロブ)に化ける。
4. **赤クレイ上の赤トレイルは尾の色相で分離不能**（H=358 が地面と同一）。**先端 H=28〜42 を使う**。
5. **サンドコート上の黄トレイルは H/S/V すべて地面と一致 → 色では分類不能**（マスクは分岐K で 81% 取れる）。
6. **★青ハード上の青スライスは彩度でも分離不能（ΔS=+0.05 のみ）**。
   court-robustness の「彩度差 +0.22 が唯一の共通信号」という結論は青×青では成立しない。
   輝度（L > コートL90+25）が主信号になる。
7. **★コート基準帯にコート外が1割でも混ざると検出が壊れる**。
   青ハードで既定の FHD 帯を使うと TP 69.5%→2.5%。帯は必ずコート台形の内側に切る。
8. **★分岐の輝度しきい値を L50 基準にすると木/ウッド/芝起伏で FP が 25〜57% に爆発する**。必ず L90 基準。
9. **★無彩色コート（石畳 S90=0.19）では Hmed が暴走する**。
   彩度 0.15 超の画素がほぼビームしか無いため、Hmed がビームの色になり色相分岐が自滅する。
   `S90 < 0.25` で色相分岐を無効化すること。
10. **白（ドロップ）トレイルは `isCourtLine`(L>175 && S<0.20) にそのまま一致する**。
    色だけではコートラインと区別できない。**3フレーム差分（0.05秒）で動く方だけ採る**のが決め手。
11. **ウッド／船ではコートラインのほうが白トレイルより暗い**（ライン L≈187 / トレイル先端 L≈204）。
    「ラインより暗い白」という上限条件は逆効果になる。
12. **白トレイルは加算合成**なので、暗いコート（船の甲板）では尾が下地の色に溶けて消える。
    先端側 1/3 でしか判定できない。
13. **マックスチャージの白フラッシュがショット色を 8〜10フレーム隠す**（0.13〜0.17秒）。
    色採取は必ずフラッシュが引いた後（打点+6フレーム）。
14. **チャージ中のキャラは虹色（白・水色・桃・黄）で全分岐に引っかかる**（実測 S90=0.69 V90=0.95 L90=216）。
    色相での除外は不可能。プレイヤー矩形をマスクするしかない。
15. キャラ固有の常時エフェクト（ゲッソーの足元の水色＝H180-200）を打球エフェクトと誤検出しうる。
16. **ラケットのスウィング弧（白い三日月）はチャージ演出ではない**。溜めなしの返球でも出る。
    pureWhite 画素数で見ると背景+95px 程度で、チャージ星（+2020px）とは桁が違う。
17. 録画解像度が動画ごとに違う（23-19-09 / 22-18-37 は 2560x1440、7本は 1280x720）。
    座標は正規化、**面積しきい値は画面比率**で持つ。
18. **ラリー中にカメラのカット/画角変更が入ることがある**（`01-57-16` の 302.75 と 304.62 で
    コートの見かけサイズが大きく違う。304.817 に1フレームで別画角へ切り替わるのを実測）。
    差分ベースの処理は、フレーム間の相関が急落したらリセットすること。
19. **フィーバー戦（`00-57-56`）は HUD が別物**（左右上端に HP/FV バー、下端に得点ピップ）。
    HUD 除外矩形をモード別に持つ必要がある。
