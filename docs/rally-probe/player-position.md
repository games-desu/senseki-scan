# ラリー解析調査: プレイヤー位置と打点

調査日: 2026-08-24 / 担当: player-position（v2 rally probe）
根拠フレームはすべて ffmpeg で実際に抜き出し、目視＋画素値実測で確認したもの。

## 判定

**検出可能だが要工夫**

- 「両者のコート上の位置」は取れる。ただし **毎フレームのコートライン検出＋ホモグラフィが必須**。
  カメラが固定でないため、画面座標のまま処理する方式（固定ROI・時間中央値背景差分・
  単純な動体差分）は**すべて破綻する**ことを実測で確認した。
- 「厳密な打点（ラケットとボールの接触点の3D位置）」は**難しい**。
  ただし **インパクト時刻の足元位置** と **バウンド位置** は取れるので、
  ラリー分析用の代替指標としては十分。
- 「色ブロブ検出」は**不可**（砂コートでキャラ本体とコート面のクロマが実測でほぼ同一）。
- 「影」は**コート依存**。使えるコートと、影がまったく出ないコートがある。

## 判明した事実

### F1. ラリー中のカメラは固定ではない（既存前提の訂正・最重要）

- `2026-08-20 10-44-35.mp4` の t=496.5〜503.5（1ラリー）を 4fps で28枚一望した結果、
  **同一ラリー中にゆっくりズームイン／ドリーする**。
  開始時は「コート全体が入る広い画」、7秒後には「ネットが画面上端いっぱい・自陣半面のみ」。
- 定量: 60fps フレーム列（480x270 に縮小）で相似変換（スケール＋並進）を推定したところ
  **100ms あたり scale ≒ 1.003〜1.012、並進 ≒ 4〜6 px（480幅換算＝FHDで16〜24px）**。
  1秒で 3〜12% のズーム。
- 同一ラリー内での見かけサイズ変化（`10-44-35.mp4`、自分＝ハナチャン、FHD換算）:
  - t=496.6（広い）: 高さ ≒ **140 px**
  - t=503.2（寄り）: 高さ ≒ **360 px**  → **同一ラリー内で約2.5倍**
- 帰結（すべて実測で確認）:
  - 12秒窓の**時間中央値背景差分は破綻**。差分マスクの最大連結成分が 45,000〜69,000 px（＝ほぼ全画面）になった。
  - **画面固定ROIも不可**（コート／ネットの画面位置が刻々変わる）。
  - 並進のみ補償した3フレーム差分はコートライン上に大量の偽陽性。
    相似変換（スケール込み）補償にすると偽陽性はかなり減り、手前選手はほぼ毎フレーム箱で取れた
    （残る偽陽性＝画面左右のスコアUIと、視差のある場外構造物）。

### F2. サーブとラリーでカメラが別物

- `10-44-35.mp4` t=300.0 はサーブ画で、**低い位置・地平線と空が画面上半分**を占める広角。ネットは y≈480-520。
- 同 t=60 / t=500 はラリー画で、自陣後方やや上からの俯瞰。空はほぼ写らない。
- `2026-08-23 01-08-30.mp4` t=120 は **フィーバーショットのカットイン**で、
  キャラが画面いっぱい（コートがほとんど見えない）。UI も HP/FV バー付きで別物。
- → 「ラリー画」だけを対象にするシーン判定が前段に必要。

### F3. 動画の解像度が3種類ある（既存前提の訂正）

`ffmpeg -i` で全13本を確認（すべて60fps）:

| 解像度 | 本数 | ファイル |
|---|---|---|
| 1920x1080 | 4 | 10-44-35, 11-02-43, 11-33-43, 22-02-04 |
| 2560x1440 | 2 | 22-18-37, 23-19-09 |
| **1280x720** | **7** | 23-37-24, 23-59-59, 00-39-45, 00-49-49, 00-57-56, 01-57-16, 01-08-30 |

- 720p が過半数。720p では奥の選手が **60〜90 px** 程度しかなく、細部は潰れる。
- vision.js の `cropRegion` は videoWidth でスケールするので座標は流用可だが、
  **面積閾値・モルフォロジーのカーネル幅は解像度に比例させる必要**がある。

### F4. キャラの見かけサイズ（実測）

| 動画 / 時刻 | コート | 手前 | 奥 |
|---|---|---|---|
| 10-44-35 t=500.0（FHD） | サンド | ハナチャン 約 **180 x 310 px**（足元 y≈920） | パタパタ 約 **105 x 125 px**（足元 y≈255） |
| 10-44-35 t=496.6（FHD・広い画） | サンド | 高さ 約 140 px | 高さ 約 130 px |
| 11-33-43 t=200.0（FHD・広い画） | 芝 | クリボー 約 **130 x 135 px**（足元 y≈990） | ピーチ 約 **60 x 145 px**（足元 y≈395） |
| 00-39-45 t=120.0（**720p**） | ウッド | ハナチャン 約 **125 x 215 px**（FHD換算 187x322） | 約 60 px 高 |

- 手前:奥 の倍率は寄りの画で約2.5倍、広い画ではほぼ等倍まで縮まる（＝**固定の倍率仮定は不可**）。

  → 「高さ○px以上を選手とみなす」ようなサイズ前提は危険。

### F5. 色ブロブ検出は原理的に不可（砂コート・実測値）

`2026-08-20 10-44-35.mp4` の実画素値（正規化クロマ = r/(r+g+b), g/(r+g+b)）:

| 対象 | RGB | クロマ | 輝度 |
|---|---|---|---|
| 日向の砂 | (218,197,102) | (0.422, 0.381) | 192 |
| パタパタの頭（黄） | (235,208,103) | (0.430, 0.381) | 204 |
| パタパタの甲羅 | (214,200,106) | (0.412, 0.385) | 193 |
| ハナチャンの胴（黄） | (233,210,104) | (0.426, 0.384) | 205 |
| ハナチャンの赤い斑点 | (230,214,113) | (0.413, 0.384) | 207 |

→ **キャラ本体と砂のクロマ差は 0.005〜0.020 しかない**。輝度差も 6% 程度。
ユーザーの懸念どおり「黄色いハナチャンの色ブロブ検出」は成立しない。**実測で確定**。

### F6. 影：コート依存。使えるコートと出ないコートがある

**影がはっきり出るコート**（実測）:

| 動画/時刻 | 影の核 RGB | 隣の日向 RGB | 輝度比 |
|---|---|---|---|
| 10-44-35 t=499.383（サンド・奥の選手の影） | (149,131,60) / (125,109,34) | (214,197,108) | **0.62〜0.67** |
| 10-44-35 t=503.183（サンド・手前の選手の影の縁） | (167,152,85) | (214,196,89) | 0.78（半影） |
| 11-33-43 t=200（芝・ピーチの影） | 目視で明瞭（濃い緑〜黒） | 明るい緑 | 高コントラスト |
| 00-39-45 t=120（ウッド720p） | 目視で明瞭。**ラケットの形まで独立に写る** | | |

**影がまったく出ないコート**（決定的な反例）:

- `2026-08-20 23-19-09.mp4` t=300（芝・丘）: **手前・奥とも影が一切ない**。
  コントラスト伸長（`lutyuv=y='clip((val-118)*7+128,0,255)'`）をかけても影は現れず、
  見えるのはキャラの黒い輪郭線と芝のまだら模様だけ。曇天／拡散光のコート。
  画素実測でも 選手直下(109,174,62) と 隣の芝(93,161,51) で差が出ない。
- → **影を主手掛かりにする設計は不可**。補助にとどめる。

**影の方向はコートごとに違う**:
- サンド（10-44-35）＝光源は右上、影は**左下**へ伸びる
- ウッド（00-39-45）＝光源は左上、影は**右下**へ伸びる
→ 影オフセットを使うなら**コートごとにキャリブレーション**が要る。

**影と足元のズレ（実測）**: `10-44-35.mp4` t=499.383 の奥の選手。
本体の足元は FHD (1005..1045, y≈205)、影の核は (935..1044, 217..263)。
影の中心は足元から **左下へ約 (-25, +25) px**（キャラ高さ106pxの約0.24倍）。
つまり影の**右上端**が接地点にいちばん近い。

**大きな建物影という罠**: サンドコートにはスタジアム屋根の巨大な影が落ちる。
実測 (126,125,74) で**キャラの影より濃い**。「暗い＝キャラの影」では確実に誤検出する。
（キャラ影はクロマがコートと同じ黄系(0.438,0.385)、建物影は空光が回り込んで
やや青寄り(0.388,0.385)、という違いはあるが差は小さく単独では頼れない）

### F7. コートライン（白線）マスクは全コートで安定して取れる ★実装の鍵

`masks.js` で試した方式が、砂／芝／赤クレイ／ウッド／青ハードすべてで
**コート内にほぼノイズなし**で白線だけを抜けた（640x360 に縮小して処理）。

```
コート面色モデル = フレーム自身の y∈[0.35H,0.92H], x∈[0.15W,0.85W] の
                   輝度中央値 CL（と正規化クロマ中央値）
白線マスク       = L > CL * 1.06  かつ  (max(R,G,B) - min(R,G,B)) < 46
```

実測した CL（640x360）: サンド 185.7 / 芝 153.0 / 赤クレイ 116.6 / ウッド 85.1 /
青ハード 82.9 / 夜クレイ 126.3

- 良好: サンド・芝・赤クレイ・ウッド・**青ハード（特にきれい）**
- ノイズ多め: **夜の森コート**（`11-02-43`／背景の葉が拾われる。ただしコート内の線は見える）、
  **石畳コート**（目地が白線と同じ特徴になる）
- → これを使えば **毎フレームのコート4隅／ライン推定 → ホモグラフィ** が現実的。

### F7b. 素のHough変換は「制約なし」だと使えない（試作して確認）

F7 の白線マスクにそのまま Hough（theta 180分割・rho 1.5px・非極大抑制）をかけ、
上位12本を6フレームに重畳して目視した結果:

- **上位を占めるのは court line ではない水平線**: 左右下のスコアUIの帯、
  金網フェンスの横桟、パラソル／観客席の縁、ネット上端の白テープ。
  votes 250〜500 でコートのサイドラインより強い。
- **サイドライン自体は上位12本に入ってはいる**（`full_500` は左ダブルスサイドライン、
  `11-33-43 t=200` は左右サイドラインが取れていた）が、選別が必要。
- **`zm_503.2` のように白い巨大フラッシュが出ているフレームでは線が総崩れ**になる。
- 必要な制約（未実装）:
  1. コート面色の最大連結領域（＝コートの多角形）内に投票を限定
  2. サイドラインは theta ∈ 約 [5°,40°] ∪ [140°,175°]、横ラインは theta ≈ 90°±8° に限定
  3. 左右サイドラインは画面上方の1点（消失点）で交わる、という整合条件で組を選ぶ
  4. UI帯（左右下スコア・上部バナー）は投票から除外
  5. フラッシュ発生フレームは前後フレームの H を内挿で埋める

### F8. インパクト（打球の瞬間）の手掛かり

`10-44-35.mp4` を 60fps バーストで精査した結果、3種類の手掛かりを確認:

1. **白い巨大な星型フラッシュ（最も強い）**
   - t=503.183 → 503.216（2フレーム=33ms）で突然出現。ラケットの接触位置を中心に
     四方に伸びる純白の星。FHD で差し渡し **400px 以上**。3〜6フレーム（50〜100ms）持続。
   - 出現初フレームの中心 ≒ **接触点（ラケット高さ。地面ではない）**。
   - ただし**全ショットには出ない**。同動画 t=499.38〜499.45 の奥の選手の返球では出ていない。
     強打／ジャストタイミングのショットに限られる模様（未確定）。
2. **白いスイング弧（swing trail）— こちらは毎回出る**
   - キャラの周囲に白〜銀の円弧状の残像＋細かいキラキラ粒子。
     t=499.32〜499.40 の奥の選手（`full_500.png` にも明瞭）で確認。
   - 選手のbbox内で「明るく低彩度な画素数」が数フレームだけ跳ね上がる、として検出できる。
3. **バウンド時の地面リング（打点ではないが極めて有用）**
   - ボールがコート面で弾むと、**白い円 → ショット色（紫/ピンク/オレンジ等）の星型バースト**
     が地面に描かれる。t=499.70〜499.90 で明瞭。`23-19-09` t=300 の SMASH でも大きな白い閃光。
   - これは**コート平面上のイベント**なので、ホモグラフィがあれば座標が正確に出る。

**ボールの進行方向反転**も原理上使えるが、ボール本体は小さく（FHDで直径15〜25px）、
ショット色のビーム（縦のカーテン状の軌跡）に隠れることが多い。単独では不安定。

## 座標・閾値（1920x1080基準）

### コート面色モデルとライン抽出（推奨・全コート共通）
- 処理解像度: 640x360 に縮小（1920→3分の1）
- コート面サンプル帯: x ∈ [0.15W, 0.85W], y ∈ [0.35H, 0.92H]
- `CL` = その帯の輝度中央値、`(CR,CG)` = 正規化クロマ中央値
- 白線: `L > CL*1.06 && (max-min) < 46`
- コート面（影含む）: `chromaDist((r,g,b),(CR,CG)) <= 0.030`
- キャラの影: `chromaDist <= 0.030 && L/CL ∈ [0.55, 0.85]`
- 建物の巨大影（サンド）: L/CL ≈ 0.55〜0.70 かつ**面積が数万px**・輪郭が直線的 → 面積で除外

### 実測画素値（サンドコート `10-44-35.mp4`）
| 対象 | RGB |
|---|---|
| 日向の砂 | (214-218, 194-205, 89-108) |
| キャラの影の核 | (125-149, 109-131, 34-60) |
| スタジアム屋根の巨大影 | (126,125,74) |
| ハナチャン胴 / パタパタ頭 | (233,210,104) / (235,208,103) |

### UI 除外マスク（ラリー画・FHD）
動体差分の偽陽性源。以下は毎フレーム除外してよい。
- 左下スコア: 約 (10,860)-(230,1050)
- 右下スコア: 約 (1690,860)-(1910,1050)
- 左上のキャラ吹き出し／レフェリー枠: 約 (0,270)-(340,400)（画によって上下する）
- 上部中央のバナー帯（ゲーム間スコア表示）: y ∈ [0,120] 全幅

### カメラ運動（相似変換近似・480x270 換算、ラリー中実測）
- 100ms あたり scale = 1.003〜1.012、並進 |d| = 4〜6 px（FHD換算 16〜24px）
- 50ms（3フレーム）あたり 並進 3〜4 px（FHD 12〜16px）

## 推奨アルゴリズム

### 全体方針
**「画面座標で頑張らない。毎フレーム ホモグラフィを求めてコート座標に落とす」**

### Step 0 — シーン判定（ラリー画だけ通す）
既存 `classify()` を拡張。ラリー画の条件案:
- 左下・右下にスコアUI（青/オレンジの丸数字）が存在
- 画面下 2/3 にコート面色が支配的（空の青が上端 10% 未満）
- ネットの網目（暗色の細かい格子）が横一直線に検出できる
サーブ画（空が広い）・フィーバーカットイン（コートがほぼ見えない・HP/FVバーあり）・
リプレイ・Winner画面は除外。

### Step 1 — コートライン検出 → ホモグラフィ（毎フレーム）
1. 640x360 に縮小し F7 の白線マスクを作る。
2. サイドライン（画面上でほぼ縦・上方に収束する2本）と
   横方向のライン（ネット直下ライン／両サービスライン／奥ベースライン）を
   RANSAC もしくは Hough で当てる。
   - **奥ベースラインはほぼ常に映る。手前ベースラインは寄りの画で画面外に出る**ので
     必須の対応点にしない。
   - 実用的な4点: 「両シングルスサイドライン × 奥サービスライン／ネット線」の交点4つ。
3. コート実寸（シングルス 8.23m × 23.77m、サービスライン 6.40m）に対応させて H を得る。
4. 前フレームの H を初期値にしてトラッキング（毎フレーム全探索しない）。

### Step 2 — 選手検出（ホモグラフィ補償差分）
1. `Hwarp = H_t · H_{t-1}^{-1}` で **前フレームを現フレームの視点にワープ**。
   コート平面上の画素は完全に一致するので、カメラのズーム／パンが厳密に打ち消される。
   （相似変換近似だけでもかなり効くことを実測済み。ホモグラフィならさらに良い）
2. 差分（グレー差 > 20〜25）→ コート四角形（マージン +1.5m）内に限定 → UI マスクを除外。
3. モルフォロジー open→close（カーネルは 解像度/480 に比例させる）→ 連結成分。
4. 足元のコートy座標で手前／奥に振り分け、各サイドの最大成分を選手とする。
5. 数フレームのトラッキング（前フレーム位置との距離でゲーティング）で欠落を補間。

補助（差分が落ちた時のフォールバック）:
- **影が出るコートなら**「クロマはコート同等・輝度比 0.55〜0.85・面積が中程度・移動する」
  塊を探す。巨大な建物影は面積と非移動性で落とす。
- キャラ本体は輪郭線が濃いので、コート内の**エッジ密度**が高い塊としても拾える。

### Step 3 — 足元（接地点）の求め方
1. 選手ブロブの **最下段3行の x 重心** を接地点とする。
   実測で、視認できる足の位置と FHD で 10〜20px 程度の誤差。
2. ただしブロブには **ラケットと影が混ざる**ので、下端を採る前に
   「クロマがコートと同じ（=影）」画素を落とす。
   **これは実測に基づく確実な分離則**: 影はコートと同クロマで暗いだけ、
   キャラ本体はクロマが違う（サンドの黄キャラだけは例外＝F5、その場合は輝度と輪郭で分ける）。
3. 接地点に H を適用してコート座標（m）へ。
4. **ジャンプ中**（`11-33-43` t=200 のピーチのように影が足元から離れる）は
   影の**光源側の端**（サンドなら右上端、ウッドなら左上端）を接地点として使う。

### Step 4 — インパクト検出
優先度順に:
1. **白い星型フラッシュ**: `L > 240 かつ (max-min) < 30` の画素の連結成分が、
   選手ブロブに接して突然出現（面積が前フレームの3倍以上に跳ねる）。
   その**初出フレーム = 打球時刻**、重心 = 接触点（空中）。
2. **スイング弧**: 選手 bbox 内の「明るい低彩度画素の割合」の時系列に鋭いピーク。
   フラッシュが出ない弱い打球でも反応する。
3. **バウンドリング**（間接）: 地面の明るいリング／星型バーストを検出して
   バウンド時刻列を作り、「バウンド → 次のバウンド」の間に打球が1回ある、と制約を張る。
4. 上記の合議。60fps なので打球時刻は ±2〜3 フレーム（±50ms）精度を狙える。

### Step 5 — 厳密な打点が取れない時の代替（推奨する実装順）
1. **インパクト時刻の足元位置（コート座標）を「打点」とする** ← 第一推奨。
   実際の接触点は足元から水平 0.3〜0.8m・高さ 0.5〜2m ずれるが、
   「どのゾーンから打ったか（ベースライン／中間／ネット前、デュース／アド）」の
   分析にはこれで十分。ゾーン分解能を 1.5m 程度に丸めれば誤差は吸収できる。
2. **直前のバウンド位置**（地面のリング）。これはコート平面上のイベントなので
   ホモグラフィで正確に座標化できる。「相手にどこへ打たせたか」の指標としては
   打点より有用な場合がある。
3. **フラッシュ重心を地面に落とす**: フラッシュ中心の画面座標を、
   足元の高さ（＝コート平面）ではなく「足元 x を保ったまま」平面に投影する近似。
   高さ由来の誤差はコート奥方向に偏るので、バイアス補正を1度キャリブレーションすれば実用可。

## 落とし穴

1. **カメラ固定を前提にしない**（F1）。中央値背景差分・画面固定ROI・単純フレーム差分は
   すべて実測で破綻。ズームは 1秒で 3〜12%。
2. **サーブ画／フィーバーカットイン／リプレイはカメラが別物**（F2）。前段のシーン判定必須。
3. **解像度が 720p / 1080p / 1440p の3種類**（F3）。面積閾値・カーネルは解像度比例に。
   720p では奥の選手が 60〜90px しかない。
4. **色ブロブは不可**（F5・実測）。砂コートでキャラと地面のクロマ差が 0.005〜0.020 しかない。
5. **影が出ないコートがある**（F6・`23-19-09`）。影は主手掛かりにしない。
6. **巨大な建物影**がコートに落ちる（サンド）。キャラの影より濃い。面積と静止性で除外。
7. **影の方向がコートごとに逆**（サンド=左下 / ウッド=右下）。
8. **キャラのサイズ差が2倍以上**（クリボー vs ハナチャン）。サイズ前提のフィルタは危険。
9. **左右下のスコアUI・左上の吹き出しは常に動く**ので動体差分の偽陽性源。マスク必須。
10. ショット色のビームは**縦のカーテン状に長く残る**（FHDで高さ400px超）。
    選手ブロブと連結してブロブを縦に伸ばす。色付き（高彩度）なので彩度で落とせる。

12. `2026-08-21 00-49-49.mp4` はラケットカタログ（試合ではない）。
