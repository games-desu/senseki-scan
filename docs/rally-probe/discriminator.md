# 打点／バウンド判別器の設計と検証

調査日: 2026-08-25 / 担当: discriminator（v3 rally probe）
根拠フレームはすべて ffmpeg で抜き出し、Read ツールで**実際に目視**して確認したもの。

## 判定

**条件付きで可能。エフェクトを一切使わずに判別できる。**

- 決め手は **「打点ではボールのコート奥行き方向(Z)が反転し、バウンドでは反転しない」** というテニスの物理。
  これを地面平面ホモグラフィの**見かけZ**で測ると、高さ h の分の系統バイアスが乗るが、
  そのバイアスは `B(Z) = (c0 + c1·Z)/K` という**閉じた式で書けて実測で検証済み**なので差し引ける。
- 人手ラベル **12イベント**（打点8・バウンド4／2動画・砂とクレイ赤）で検証:
  - 正解時刻を与えた場合 → **判定できた11件は11件とも正解**（残り1件は追跡がボールを再捕捉できず UNKNOWN）。
    打点 qc = 0.252〜1.078 / バウンド qc = −0.222〜+0.008。**しきい値 0.15 で分離、マージン約1.6倍**。
  - **追跡から通しで走らせても12件中11件の種別が正解**（§8-2）。時刻誤差 0.03〜0.12秒（1件だけ0.29秒）。
- **ただし偽イベントが多い**（22秒で13件）。原因は判別器ではなく**ラリー画のシーン判定が無いこと**と
  **チャージオーラ／打撃バーストの塊が鎖になること**。前段の整備が必須。
- **とびつき（エフェクト無し）でも動く**。実例 t=387.55 のハナチャンのとびつきは qc=0.349 で正しく打点判定。
- **白い閃光（マックスチャージ）は打点マーカーとして使えない**ことを2例で確認（下記 §2）。
- **影(ball↔shadow の dy)は 960x540 では再現できなかった**（§5）。主判定に使ってはいけない。
- 未解決: **奥コートのバウンドの実例が1件も採れなかった**（§7）。式は左右対称なので理屈上は動くが未検証。

   「白フラッシュ＝マックスチャージ完了の合図」であって、打つかどうか・いつ打つかとは独立している。
   （クレイの例が「完了フラッシュ」なのか「インパクト閃光」なのかは本調査では区別していない＝未確認。
   いずれにせよ**時間オフセットが安定しないので打点マーカーには使えない**。）
   **`ball.js` の `events()` にある `nearFlash → kind:'hit'`（±0.09秒窓）は誤り**:
   砂の例（ずれ0.12〜0.27秒）は窓から外れて打点を取りこぼし、
   逆にチャージだけしてキャンセルした場合は打点でない位置に hit を作る。
   また `Tracker.isFlash` によるフレーム破棄は、チャージ完了フラッシュのたびに
   **打点と無関係な位置で 7〜10 フレームの欠測を作る**ので、判別器はその欠測を前提に設計する必要がある。

**打撃エフェクトの実観測（打点側の副産物・詳細は impact-effects 担当へ）**:
接触フレームで**ボールの位置に白い円環が生まれ、8〜12フレームかけて拡大し、ショット色の星型バーストに変わる**。

**バウンドではこの円環は出ない**（砂 389.23 のバウンドは煙も輪も出ずボールが跳ねるだけ）。
ただし**とびつき(387.55)では小さな白い輪しか出ず色バーストは無い**ので、エフェクト単独では取りこぼす。

## 4. エフェクトに依存しない手掛かりの実測評価

### 4-1. ★本命: 「見かけZの離脱速度」（高さバイアス補正つき）

**原理**
テニスでは打点でボールのZ方向の進行が反転し、バウンドでは反転しない。
ところが地面平面ホモグラフィが返す**見かけZ**は、ボールが高さ h にあると

```
Z_app = Z_true + h · B(Z),     B(Z) = (c0 + c1·Z) / K        [m / m]
```

だけ**カメラから遠い側（+Z側）へずれる**。イベント直後は打点でもバウンドでも必ず dh/dt>0 なので、
見かけZ の速度に **+B·ḣ** のバイアスが乗る。手前側(Z<0)ではこのバイアスが打点と同じ向き、
奥側(Z>0)では逆向きに効く。**だから素の見かけZ速度では手前と奥で符号規約が食い違う。**

`B(Z)` の実測検証（10-44-35 t=386.40・打点フレーム）:
ボールの見かけ Z=8.98、**同フレームのゲッソーの足元** FHD(852,259) の Z=7.83 → 差 **+1.15 m**。
式は `B(7.83)=3.93` なので、ラケット高 h=0.29 m と読める。ゲッソーは背が低く、
目視でもボールは足元から30cm程度の低い位置にあった。**式と実測が0.05m以内で合う。**

**特徴量**

```
s   = sign(Z_evt)                       // +1=奥, -1=手前
dZ  = イベント後 0.03〜0.50 秒の見かけZ の最小二乗傾き [m/frame]
q   = -s · dZ                           // 「相手側へ進んだ速さ」
qc  = q + s · B(Z_evt) · ḣ ,  ḣ = 0.07 m/frame (≒4 m/s)   ← 高さバイアスの補正
判定: qc > 0.15 → 打点 / qc <= 0.15 → バウンド
```

**実測結果（12イベント）**

|---|---|---|---|
| バウンド 385.19 | 手前 | **+29.8** | -0.6 |
| バウンド 387.22 | 手前 | **+26.1** | +3.3 |

| 打点 122.30 | 手前 | +19.8 | **-29.8** |
| 打点 383.79 | 手前 | +21.4 | (-30 相当) |

| 打点 384.48 | **奥** | (欠測) | **+0.4** |
| 打点 119.70 | **奥** | -5.7 | +13.1 |

- **手前側**: バウンドは vOut が -15〜+3（ほぼ止まる）、打点は vOut が -24〜-30。**|vOut| ≥ 20 px/f で分離できる。**
  幾何的な理由: 手前バウンド直後は「上昇による画面下向き成分」と「カメラへ接近する画面下向き成分」が
  ほぼ相殺する。打点直後は「上昇」と「遠ざかる」が両方 画面上向きに効いて足し算になる。
- **奥側**: 打点の vOut がわずか +0.4〜+13 px/f しかない（遠近圧縮で1px≒0.05m）。
  **奥側では画面px速度は使えない。必ず見かけZ（メートル）に直すこと。**
- vIn は打点・バウンドどちらも「自陣ベースライン方向へ接近」なので**判別力は無い**（入射脚は同一）。

### 4-3. 側の交替（構造的制約）— HMMの遷移として使える

砂ラリーの確定列: `打点(手前) → 打点(奥) → バウンド(手前) → 打点(手前) → 打点(奥) → バウンド(手前) → 打点(手前) → バウンド(手前)`
クレイ: `バウンド(手前) → 打点(手前) → 打点(奥) → … → 打点(手前)`

確認できた規則（12イベントすべてで成立）:
1. **打点は必ず側が交替する**（手前→奥→手前…）。実測 5連続で成立。
2. **バウンドは必ず「次に打つ側」で起きる**。奥の打点の次のバウンドは手前、逆も同様。
3. **連続する2イベントが同じ側なら、その並びは (バウンド, 打点) の順**。
4. **打点と打点の間のバウンドは0個か1個**（0個＝ボレー）。実測でボレーが多い（12件中3件が打点→打点直行）。

時間間隔（参考・分離力は弱い）:
- 打点→バウンド: 0.71 / 0.80 s
- バウンド→打点: 0.20 / 0.33 / 1.31 s
- 打点→打点（ボレー）: 0.69 / 1.03 / 1.14 s
→ **「バウンド→打点は短い」は成り立たない**（高く弾んだ 117.25 は 1.31 s）。順序制約だけ使うこと。

### 4-4. 見かけZの絶対値・イン/アウト判定

- バウンドの見かけZ = 真のZ（h=0）なので **`inCourt()` がそのまま使える**。
  実測 4バウンド: Z=-8.99 / -5.21 / -10.94 / -9.65、|X| は 3.3〜3.5 → すべてコート内で妥当。
- 打点の見かけZ は h·B(Z) だけ奥へずれる。奥側では B≒4 なので **ラケット高0.9mで約3.6m の誤差**。
  実測 119.70 の打点は見かけ Z=+13.91 で**ベースライン(11.885)より奥に出る**。
  → **|Z_app| > 12.5 の終端は「バウンドではない」と断言してよい**（アウトのバウンドは別途扱い）。
- 逆に |Z_app| < 12.5 でも打点はありうる（384.48 は +11.78、386.42 は +7.71）。単独では使えない。

### 4-5. 「相手側に到達したか」（ネット越え判定）

イベント後、次のイベントまでの間に見かけZが 0 を越えて相手側に入るか:
- 打点 8件: 383.79→+9.96 / 384.48→-7.5 / 385.39→+0.54 / 386.42→-3.0 / 387.55→+18.9 / 118.56→+4.8 / 122.30→+18.0 …**7件で越える**
- バウンド 4件: -9.89 / -5.34 / -7.81 / -3.53 …**1件も越えない**
- 例外 119.70（奥の打点）は追跡が Z=+0.4 で切れて越えを確認できず。

→ **確度の高い裏取りにはなるが、必ず「次のイベントまで」で打ち切ること**。

## 8. 推奨アルゴリズム（`tools/ball.js` の `bounces()` 置き換え）

現状の `bounces()` は「降下したまま終わった鎖の終端」を**すべて** `segment-end` として出している。
以下はそれを **打点/バウンド/不明** の3値に分類する差し替え版。**エフェクトを一切参照しない。**

```js
  // ---- 打点／バウンド判別 ----
  // 原理（docs/rally-probe/discriminator.md）:
  //   テニスでは「打点で奥行きZの進行が反転し、バウンドでは反転しない」。
  //   地面平面ホモグラフィが返す見かけZは高さhの分だけ +Z 側にずれる:
  //       Z_app = Z_true + h * B(Z),   B(Z) = (c0 + c1*Z) / K        ← 実測で0.05m以内に一致
  //   イベント直後は打点もバウンドも dh/dt>0 なので、見かけZ速度に +B*ḣ のバイアスが乗る。
  //   側 s(+1=奥/-1=手前) で符号を揃え、このバイアスを引くと 12件中 判定できた11件が11件正解。
  //   しきい値 0.15 m/frame。打点 0.252〜1.078 / バウンド -0.222〜+0.008。
  const HDOT = 0.07;          // イベント直後の典型的な上昇速度 [m/frame] ≒ 4 m/s
  const QTHRESH = 0.15;       // qc のしきい値 [m/frame]

  // 見かけZの「高さ1mあたりの押し出し量」。court.js の cam から閉じた式で出る。
  function zBias(Z, cam) { return (cam.c0 + cam.c1 * Z) / 0.2796e-3; }

  // segments（ballSegments の出力）を1本の時系列に畳む
  function mergeTrack(segments) {
    const pts = [];
    segments.forEach((s, si) => s.pts.forEach(p => pts.push({ ...p, seg: si })));
    return pts.sort((a, b) => a.t - b.t);
  }

  // 直線フィット（Z vs frame）。返り値 m/frame
  function slopeZ(seq) {
    const n = seq.length; if (n < 3) return null;
    let sf = 0, sz = 0, sff = 0, sfz = 0;
    for (const p of seq) { sf += p.f; sz += p.Z; sff += p.f * p.f; sfz += p.f * p.Z; }
    const d = n * sff - sf * sf;
    return Math.abs(d) < 1e-9 ? null : (n * sfz - sf * sz) / d;
  }

  // イベント候補の抽出（★画面yの反転では足りない）
  //  実測: 弱いバウンド(387.22)は画面yが反転せず +26→+2 px/f と減速するだけ。
  //        地面のボールを掬うとびつき(387.55)も反転しない。奥側の打点は画面yがほとんど動かない。
  //  → **見かけZ速度の折れ（kink）**を主候補にする。鎖の端は補助。
  //  パラメータは実測で調整済み: W=6フレーム / kink>=0.18 m/frame / 非極大抑制 ±3標本 / 統合 0.12秒
  function eventCandidates(segments, track) {
    const out = [];
    for (const s of segments) {
      const p = s.pts; if (p.length < 4) continue;
      out.push({ t: p[p.length - 1].t, x: p[p.length - 1].x, y: p[p.length - 1].y, src: 'seg-end' });
      out.push({ t: p[0].t, x: p[0].x, y: p[0].y, src: 'seg-start' });
    }
    const W = 6;
    const sl = (a, b) => {                      // 最小二乗 Z vs frame
      let n = 0, sf = 0, sz = 0, sff = 0, sfz = 0;
      for (let i = a; i <= b; i++) { const p = track[i]; if (!p || !isFinite(p.Z)) continue; n++; sf += p.f; sz += p.Z; sff += p.f * p.f; sfz += p.f * p.Z; }
      if (n < 4) return null;
      const d = n * sff - sf * sf; return Math.abs(d) < 1e-9 ? null : (n * sfz - sf * sz) / d;
    };
    const kink = new Array(track.length).fill(0);
    for (let i = W; i < track.length - W; i++) {
      if (track[i + W].f - track[i - W].f > 3 * W) continue;    // 欠測が多すぎる区間は使わない
      const A = sl(i - W, i - 1), B = sl(i + 1, i + W);
      if (A != null && B != null) kink[i] = Math.abs(B - A);
    }
    for (let i = W; i < track.length - W; i++) {
      if (kink[i] < 0.18) continue;
      let isMax = true;
      for (let k = -3; k <= 3; k++) if (kink[i + k] > kink[i]) { isMax = false; break; }
      if (isMax) out.push({ t: track[i].t, x: track[i].x, y: track[i].y, src: 'kink' });
    }
    out.sort((a, b) => a.t - b.t);
    const merged = [];
    for (const e of out) {
      const last = merged[merged.length - 1];
      if (last && e.t - last.t < 0.12) {                        // 二重計上を潰す。kink を優先
        if (last.src !== 'kink' && e.src === 'kink') merged[merged.length - 1] = e;
        continue;
      }
      merged.push(e);
    }
    return merged;
  }

  // 打点時刻の精密化: 前後の鎖を1次でフィットして交点を取る。
  // **向きの変化が大きい軸で解く**こと（実測: 強打は画面yがほぼ動かず画面xだけ反転する）。
  function refineTime(track, e) {
    const before = track.filter(p => p.t < e.t && p.t >= e.t - 0.14);
    const after  = track.filter(p => p.t > e.t && p.t <= e.t + 0.30);
    if (before.length < 3 || after.length < 3) return e.t;
    // 独立変数は t（秒）そのもの。傾き a は px/秒
    const lin = (seq, key) => {
      const n = seq.length; let st = 0, sv = 0, stt = 0, stv = 0;
      for (const p of seq) { st += p.t; sv += p[key]; stt += p.t * p.t; stv += p.t * p[key]; }
      const d = n * stt - st * st; if (Math.abs(d) < 1e-9) return null;
      const a = (n * stv - st * sv) / d;
      return { a, b: (sv - a * st) / n };
    };
    let best = null;
    for (const key of ['x', 'y']) {
      const A = lin(before, key), B = lin(after, key);
      if (!A || !B) continue;
      const dv = Math.abs(A.a - B.a);
      if (dv < 60) continue;                    // 傾きが実質変わらない軸は使わない (px/s)
      const tX = (B.b - A.b) / (A.a - B.a);
      if (!best || dv > best.dv) best = { dv, t: tX };
    }
    if (!best) return e.t;
    return (best.t > e.t - 0.30 && best.t < e.t + 0.30) ? best.t : e.t;
  }

  // ---- 本体 ----
  // segments: ballSegments の出力（pts に t,f,x,y[960空間] を持つ）
  // camAt(t): その時刻の Court.estimate 結果
  function classifyEvents(segments, camAt, opts = {}) {
    const margin = opts.margin ?? 0.6;
    const qth = opts.qThresh ?? QTHRESH;
    const track = mergeTrack(segments).map(p => {
      const cam = typeof camAt === 'function' ? camAt(p.t) : camAt;
      const c = cam && cam.ok ? Court.toCourt(p.x * SC, p.y * SC, cam) : { X: NaN, Z: NaN };
      return { ...p, X: c.X, Z: c.Z, cam };
    });
    const cands = eventCandidates(segments, track);
    const out = [];
    for (let i = 0; i < cands.length; i++) {
      const e = cands[i];
      const tEvt = refineTime(track, e);
      const at = track.reduce((b, p) => (!b || Math.abs(p.t - tEvt) < Math.abs(b.t - tEvt) ? p : b), null);
      if (!at || !at.cam || !at.cam.ok) { out.push({ t: tEvt, x: e.x, y: e.y, kind: 'unknown' }); continue; }
      const s = at.Z >= 0 ? 1 : -1;
      // 次のイベントの手前で打ち切る（打ち切らないとバウンド直後の打点を拾って誤判定する）
      const tStop = Math.min(tEvt + 0.50, (cands[i + 1] ? cands[i + 1].t : Infinity) - 0.06);
      // 入射脚との連続性ゲート（バーストの塊を掴まないため）: 40px/frame + 40px @FHD
      const gate = p => {
        const df = Math.max(1, (p.t - tEvt) * 60);
        return Math.hypot((p.x - at.x) * SC, (p.y - at.y) * SC) <= 40 * df + 40;
      };
      let seq = track.filter(p => p.t >= tEvt + 0.03 && p.t <= tStop && gate(p));
      if (seq.length >= 3 && seq[seq.length - 1].t - seq[0].t < 0.08)
        seq = track.filter(p => p.t >= tEvt + 0.03 && p.t <= Math.min(tEvt + 0.7, tStop) && gate(p));
      const dZ = slopeZ(seq);
      let kind = 'unknown', qc = null;
      if (dZ != null && seq.length >= 3) {
        qc = (-s * dZ) + s * zBias(at.Z, at.cam) * HDOT;
        kind = qc > qth ? 'hit' : 'bounce';
      }
      // 幾何の常識で上書き: 見かけZが |12.5| を超える点は地面ではありえない
      if (kind === 'bounce' && Math.abs(at.Z) > 12.5) kind = 'hit';
      out.push({
        t: tEvt, x: at.x, y: at.y, kind, qc: qc == null ? null : +qc.toFixed(3),
        side: s > 0 ? 'opp' : 'me',
        X: +at.X.toFixed(2), Z: +at.Z.toFixed(2),
        inCourt: Court.inCourt(at.X, at.Z, margin),
      });
    }
    return applyRallyRules(out);
  }

  // 構造制約で後始末（12イベントすべてで成立を確認した規則）
  //  1. 打点は側が交替する          2. バウンドは「次に打つ側」で起きる
  //  3. 同じ側の連続2イベントは (バウンド, 打点) の順
  //  4. 打点と打点の間のバウンドは0個か1個
  function applyRallyRules(evs) {
    for (let i = 0; i < evs.length; i++) {
      const a = evs[i], b = evs[i + 1];
      if (a.kind === 'unknown' && b && b.kind === 'hit' && b.side === a.side) a.kind = 'bounce';   // 規則3
      if (a.kind === 'unknown' && b && b.kind === 'bounce' && b.side !== a.side) a.kind = 'hit';   // 規則2
      if (a.kind === 'bounce' && b && b.kind === 'bounce' && a.side !== b.side) a.kind = 'hit';    // 規則2の逆
    }
    // 打点の側が2回続けて同じなら、その間に取りこぼした打点があるので警告フラグ
    let prevHit = null;
    for (const e of evs) {
      if (e.kind !== 'hit') continue;
      if (prevHit && prevHit.side === e.side) e.suspect = 'same-side-hits';
      prevHit = e;
    }
    return evs;
  }
```

**呼び出し側の変更**: 既存の `bounces(segments, cam)` は
`classifyEvents(segments, camAt).filter(e => e.kind === 'bounce')` に置き換えられる。
打点列は `.filter(e => e.kind === 'hit')` で同時に取れる。

**併せて直すべき3点**
1. `events()` の `nearFlash ? 'hit' : 'bounce'` を撤去する（§2 で誤りと確定）。
2. `buildChains` の `path.length = 0; break;` を `break;` にして鎖の取りこぼしを止める（§7）。
3. `events()` の「画面yの極大」だけでは弱いバウンドととびつき打点を取りこぼす。
   候補抽出は上記の **見かけZ速度の折れ（kink）** に置き換える。
