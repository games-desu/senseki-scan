## 判明した問題と対処（すべて同日適用・検証済み）

### 1. 未収穫バナーが既存テンプレに閾値超えで誤マッチ（誤名の主因）
「アイスフラワーブースト」（辞書未収穫）が**オシダシーラケットのテンプレに xcorr 0.91**で誤マッチ
（閾値0.85）。証拠クロップの目視で全12サンプルがアイスフラワーブーストと確定。
→ **収穫で解消**: アイスフラワー1本・メタル2本を追加（racketBanners 74→77）。
再分類でアイスフラワー0.998〜1.0・実オシダシーブースト(m1相手)は0.99のまま・
前回収穫40イベントの判定変化ゼロ（回帰なし）。

### 2. 斜め表示バナーが findBanner の maxH=110 を超えて検出漏れ
メタルブーストは**斜めに傾いたまま静止する**表示で、文字ボックス高がFHD実測131px。
collectBanners が捕まえられたのはスライド中の1フレームだけ（プロファイル劣化で0.82→null）。
→ **collectBanners のバナー探索のみ `{maxH:160}`**（勝敗パネル棄却ガード等の他の呼び出しは既定のまま）。
修正後の実機テスト: t289.9で**メタルラケット@1.00・side=opp（dropR 0.38）**＝GT一致。

### 3. 偽バナー「パトカーふんさい」（コートギミック演出の帯）による過剰フラグ
黒帯+小文字の演出テキストが racketEvents に混入（score 0.43〜0.53・name null）し、
旧ロジック「null イベントがあれば両側フラグ」で**全問正解の m3 までフラグ**されていた。
→ フラグ精緻化: **score<0.7 の未照合イベントはフラグ根拠にしない**＋
**side不明でも名前が確定済みラケットと同じなら矛盾なし**（index.html）。

### 4. GT側の疑義（ユーザー確認待ち）
m1（00:00 キャサリン vs ベビィワリオ 7-4）の相手はDB登録「アイスフラワーラケット」だが、
動画には**「オシダシーブースト」バナーが相手側で2回（xcorr 0.99）**映っている
（自分側はアイスフラワーブースト）。DB側の登録誤りの可能性が高い。
→ 定石「GT側の目視も誤りうる」の新実例（バナー0.99は名前の強い証拠になる）。

クロップが見切れて見える件を実測調査した結論:
