## 7. スコアの妥当性検証を追加（4→6誤読の網・最重要）
「7-6」はありえないのに赤枠にならなかった実例あり（4→6誤読・通算6例目）。
**FEVER の isValidScore と同じ規則を検証に追加する**:

```
有効な最終スコアは「7 対 0〜5」か「8 対 6」だけ
（mario-tennis-records/components/MatchForm.tsx の isValidScore・L421〜427）
```

**重要（ユーザー指示）: 無効なスコアはフラグを立てるだけでなく、そのまま表示しないこと。**
ありえない数字と分かっているのだから、**妥当性制約の下で読み直して値を置き換えてから表示**する:
1. readGlyphs/parseNumber は各桁のテンプレ照合スコアを持っている。1位の解釈が無効なスコアを
   作るなら、**2位以下の候補のうち有効なスコアになる読みを採用**する
   （例: 7-6 → 相手側は 0〜5 のどれか。「6」の次点候補が「4」なら 7-4 に置き換える）。
2. 片方が高信頼なら isValidScore の補完規則で他方を絞り込める（7→相手は0〜5 / 8→相手は6 / 6→相手は8）。
3. 置き換えた値には必ず要確認フラグを付ける（自動補正であることが分かるように）。
4. どの候補でも有効にならない場合だけ空欄＋フラグ（**無効な数字を出力に残すのは禁止**）。
数字テンプレの根本対策（lightink「4」）の前に、この制約付き読み直しだけでも入れる価値が高い。
FEVER側には「片方を入れるともう片方を自動補完する」UX（8→6・6→8・≤5→7）もあるので、
修正UIでも同じ補完を入れると入力が速くなる。
