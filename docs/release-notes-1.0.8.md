## 1. 対戦後レートが変動前のまま入る

### 症状
レートパネルは「変動前の値で静止 → カウント演出 → 変動後の値で静止」と遷移する。アプリはパネル表示中を0.4秒刻みで全走査し、
**最初の安定値（同じ値が2回以上）＝変動前 / 最後の安定値＝変動後**として読む。安定値が1つしか取れなかったときは
「カウント演出を映さずスキップされた＝最後に見えている値が確定値」とみなして**変動後**に入れていた。

ところが今回は逆で、**カウント前の静止だけが読めて、カウント後の静止を取り逃していた**。実測すると当該パネルは
3174 が1.8秒・カウント1.6秒・3163 が1.6秒。数字の確信度は 0.58〜0.62 で受理ライン0.60ぎりぎり（ゲーム画面が
フルHDの73%＝数字が小さい録画のため）で、3163 側が数フレーム落ちると安定値が 3174 の1つだけになる。

さらに次の試合（m5）は変動前 3163 を画面から正しく読めていたのに、後段の「レート連鎖補完」が
**前試合のafter（誤った3174）で上書き**していた。つまり誤りが1試合先まで伝播していた。

### 修正
- 安定値が1つだけのとき、その値が**前試合の確定レートと同じなら「変動前」**として扱う（レートは1試合ごとに必ず動くため、
  同値なら変動後ではありえない）。変動後は空にして要確認にする
- レート連鎖の**逆向き補完**を追加。前試合の変動後が空、または前後同値のときは、次試合の画面から読めた変動前で埋める。
  誤読を持ち込まないよう「前試合の変動前との差が±200以内」「勝敗と増減の向きが合う」ときだけ採用する
- 画面読みと連鎖が一致しているときは、値をいじらずログにも出さない（従来は毎試合「補完」と出ていた）

`tools/chain-test.js` に、報告のログ10試合ぶんを流して直ることを確認する回帰テストを置いた。

## 2. ミラー戦で相手キャラの色違いを取り違える

### 症状
VS画面のアイコン照合は2段階で、①輝度だけのNCCでキャラ（ベース名）を決め、②同じキャラに色違いがあるときだけ
「カード背景色に近いセルを灰色に潰した」色つきNCCで色を決める。

②のカード色の推定が**アイコン枠の左端3列の平均**だった。しかしVSカードの左端には**ランクバッジとラケットの柄**が入り、
下の行はキャラ本体なので、地の色になっていない（実測: 橙カードの相手側ヘイホーで推定値が #833d62＝橙と赤の混色）。
その結果マスクがまったく効かず、色つきNCCが「キャラの色」ではなく**カードの色**で決まっていた。
だから相手側（橙カード）の赤ヘイホーが、同じ橙カードで採った**ヘイホー:青**に化けた（正解の無印は7色中の最下位 0.460）。

### 修正
- カード色の推定を**右端3列の中央値**に変更（バッジもラケットも無く、キャラに覆われにくい帯）。
  辞書316本中307本がこれで青／橙のどちらかに寄る。残る9本（ボスパックン等の巨体でカード地が見えないもの）は
  カード色の既定値2種で落とす
- それでもヘイホーは**白い仮面が面積の大半**で、色違い同士のスコアが団子になる（実測 ピンク0.827 / 無印0.826＝0.001差）。
  さらに縮小された録画はにじみで赤が薄れ、絶対色で比べると赤がピンクに寄る。
  → **「彩度がいちばん高いセル上位12個の平均色」の近さ**を3割混ぜた（にじんでも色の芯は残る）。
  配合は 色つきNCC 7 : 芯の色 3
